# Star Player UI/UX GUIDE v1.8

## 1. 문서 목적

이 문서는 `Star Player`의 UI/UX 구현 방향을 정리한 개발 가이드다.

이 문서의 목적은 완성된 비주얼 디자인을 확정하는 것이 아니다.

목표는 다음과 같다.

- Codex가 개발 로드맵을 설계할 때 UI 작업 범위를 판단할 수 있도록 한다.
- Godot UI 구현 시 화면 구조와 정보 우선순위를 일관되게 유지한다.
- Prototype 단계에서 불필요한 UI 과투자를 방지한다.
- 게임 로직과 UI를 분리한다.
- 플레이어가 한 명의 야구 선수 커리어에 집중할 수 있는 정보 구조를 만든다.

현재 단계에서는 색상, 폰트, 아이콘, 세부 애니메이션 등 최종 비주얼 스타일은 확정하지 않는다.

---

# 2. UI 핵심 목표

Star Player의 UI는 다음 원칙을 따른다.

## 2.1 선수 중심

게임은 감독 / 단장 시뮬레이션이 아니라 한 명의 선수를 플레이하는 게임이다.

따라서 모든 화면은 다음 질문을 기준으로 설계한다.

> 지금 이 정보가 플레이어 자신의 커리어 판단에 필요한가?

구단 전체 운영 정보보다 플레이어 선수에게 직접 관련된 정보를 먼저 보여준다.

---

## 2.2 정보 중심 PC UI

Football Manager, OOTP와 같은 정보 중심 PC 인터페이스를 참고한다.

다만 화면 복잡도는 가능한 한 낮춘다.

중요한 정보는:

- 현재 선수 상태
- 다음 경기
- 최근 성적
- 팀 내 입지
- 훈련
- 계약
- 뉴스
- 주요 이벤트

순으로 빠르게 확인할 수 있어야 한다.

---

## 2.3 한 화면에 너무 많은 정보를 넣지 않는다

모든 정보를 한 화면에 보여주지 않는다.

다음과 같이 계층을 나눈다.

```text
핵심 정보
↓
요약 정보
↓
상세 정보
```

예:

```text
홈
→ 현재 성적 요약

내 선수
→ 능력치 / 상태 / 평가

기록
→ 시즌 / 통산 상세 기록
```

---

## 2.4 플레이 흐름을 끊지 않는다

일반적인 게임 진행은 가능한 한 다음 흐름 안에서 해결한다.

```text
홈
↓
다음 일정 확인
↓
훈련 / 생활 선택
↓
경기
↓
경기 결과
↓
뉴스 / 이벤트
↓
다음 날짜
```

화면 전환이 지나치게 많아지지 않도록 한다.

# 3. 전체 화면 구조

기본 PC 레이아웃은 다음 구조를 사용한다.

```text
┌─────────────────────────────────────────────────────────────┐
│ 상단 상태 바                                                │
│ 날짜 / 시즌 / 소속팀 / 현재 일정 / 진행 버튼                │
├──────────────┬──────────────────────────────┬───────────────┤
│              │                              │               │
│ 좌측 메뉴    │        메인 콘텐츠           │ 우측 정보     │
│              │                              │ 패널          │
│ 홈           │                              │               │
│ 내 선수      │                              │ 최근 뉴스     │
│ 경기         │                              │ 다음 일정     │
│ 일정         │                              │ 알림          │
│ 훈련         │                              │ 주요 이벤트   │
│ 기록         │                              │               │
│ 팀           │                              │               │
│ 리그         │                              │               │
│ 계약         │                              │               │
│ 자산         │                              │               │
│ 생활         │                              │               │
│ 인간관계     │                              │               │
│ 뉴스         │                              │               │
│ 커리어       │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 필요 시 하단 알림 / 상태 / 툴팁                             │
└─────────────────────────────────────────────────────────────┘
```

모든 화면에서 좌측 메뉴와 상단 상태 바를 가능한 한 유지한다.

경기 화면이나 대형 이벤트에서는 예외적으로 전체 화면 모드를 사용할 수 있다.

# 4. 상단 상태 바

상단 상태 바에는 게임 진행에 필요한 최소 정보를 배치한다.

기본 항목:

- 현재 날짜
- 현재 시즌
- 소속팀
- 1군 / 2군 상태
- 다음 일정
- 현재 경기 여부
- 게임 진행 버튼

예:

```text
2031년 6월 17일
두산 베어스
1군
다음 경기: vs LG
[다음 일정 진행 ▶]
```

중요 이벤트가 대기 중일 경우:

```text
[계약 협상 대기]
[부상 치료 선택 필요]
[국가대표 발표]
```

같은 상태를 표시한다.

# 6. 홈 화면

홈은 가장 중요한 화면이다.

플레이어가 게임을 켰을 때:

> 지금 내 선수가 어떤 상태이고 무엇을 해야 하는가?

를 바로 이해할 수 있어야 한다.

## 6.1 기본 정보

예:

```text
김OO
24세 / SS
두산 베어스

1군 주전
```

---

## 6.2 시즌 성적

타자 예:

```text
G     AVG    HR    RBI    OPS
72    .302   17    54     .891
```

투수 예:

```text
G     W-L    ERA    IP     SO
18    11-4   2.83   112.1  126
```

투타 겸업 선수는 타자 / 투수 요약을 모두 표시할 수 있다.

---

## 6.3 현재 상태

예:

```text
컨디션       91
피로도       24
경기 감각    88
스트레스     31
만족도       76
```

부상 상태가 존재하면 일반 상태보다 우선 노출한다.

---

## 6.4 팀 내 상태

예:

```text
팀 내 입지
주전

감독 신뢰
높음

최근 출전
7경기 연속 선발
```

정확한 내부 인간관계 수치보다 상태 표현을 우선한다.

---

## 6.5 다음 행동

홈 화면에서 가장 눈에 잘 띄는 영역에 다음 행동을 배치한다.

예:

```text
다음 경기
6월 18일
두산 vs LG

[경기 진행]
```

또는:

```text
오늘은 경기가 없습니다.

[훈련 선택]
[휴식]
[생활 활동]
```

# 7. 내 선수 화면

내 선수 화면은 플레이어 캐릭터의 상세 정보를 관리한다.

탭 예:

```text
프로필
능력치
상태
포지션
평가
커리어
```

---

## 7.1 프로필

표시 정보:

- 이름
- 나이
- 생년월일
- 출신
- 신장 / 체중
- 투타
- 주 포지션
- 보조 포지션
- 소속팀
- 등번호
- 계약 상태
- 병역 상태

---

## 7.2 능력치

플레이어 자신의 현재 기본 능력치는 정확한 숫자로 보여준다.

타자:

```text
컨택       68
파워       72
선구안     61
주루       74
수비       66
송구       70
```

투수:

```text
구위       72
제구       64
구속       76
체력       70
```

구종:

```text
패스트볼   75
슬라이더   68
체인지업   56
```

실제 잠재력 숫자는 표시하지 않는다.

---

## 7.3 잠재력 관련 정보

잠재력은 정확한 값 대신 평가 표현만 제공한다.

예:

```text
코치 평가

"현재 성장 속도가 좋은 편이다.
장기적으로 리그 주전급 이상으로 성장할 가능성이 있다."
```

또는:

```text
성장 기대
높음

평가 신뢰도
보통
```

# 8. 경기 화면

경기 UI의 목표는 야구 액션을 직접 조작하는 것이 아니라 상황 판단과 선택에 집중하게 하는 것이다.

## 8.1 기본 구조

경기 화면 중앙에는 **야구장 다이어그램**을 배치한다.

야구장 다이어그램은 현재 수비 배치와 주자 상황을 한눈에 이해할 수 있도록 하는 핵심 시각 요소다.

기본 구조 예:

```text
┌────────────────────────────────────────────────────────────┐
│ 7회말 / 2사 / 1,3루                                       │
│ 두산 2 : 3 LG                                             │
├───────────────────────┬────────────────────────────────────┤
│ 현재 타자             │            야구장 다이어그램        │
│ 3번 김OO / LF         │                                    │
│ 타율 .317 / HR 18     │               CF 김OO              │
│ 컨택 72 / 파워 68     │                                    │
│ 주루 61               │      LF 박OO            RF 이OO    │
│                       │                                    │
│ 상대 투수             │          SS 최OO   2B 정OO         │
│ 박OO / 우투           │                                    │
│ 구속: 빠름            │      3B 한OO            1B 오OO    │
│ 제구: 보통            │                             [주자]   │
│                       │                             이OO     │
│ 카운트 1-1            │                             주루 78  │
│                       │                                    │
│ [적극 타격] [컨택]    │               P 임OO               │
│ [장타] [기다리기]     │                                    │
│ [직구 노림]           │               C 강OO               │
│ [변화구 노림]         │                                    │
└───────────────────────┴────────────────────────────────────┘
```

수비팀은 야구장 위에 직접 표시하고, 공격팀은 현재 타자와 베이스에 진루한 주자만 표시한다.

---

## 8.2 경기 화면 우선 정보

타자:

- 이닝
- 점수
- 아웃 카운트
- 주자 상태
- 볼카운트
- 상대 투수 정보
- 현재 컨디션
- 선택 가능한 타격 전략

투수:

- 이닝
- 점수
- 아웃 카운트
- 주자 상태
- 볼카운트
- 상대 타자 특성
- 현재 피로도
- 구종 상태
- 선택 가능한 투구 전략

---

## 8.3 경기 결과

선택 후 결과는 즉시 이해할 수 있어야 한다.

예:

```text
결과

좌중간 2루타!

2루 주자 득점
1루 주자 3루 진루

두산 3 : 3 LG
```

이후:

```text
[다음 상황]
```

으로 진행한다.

---

## 8.4 경기 진행 모드

지원 예정:

- 내 타석만 보기
- 내 투구 상황만 보기
- 중요한 상황만 보기
- 전체 경기 보기
- 경기 결과까지 빠르게 진행

UI는 현재 선택한 진행 모드를 항상 확인할 수 있도록 한다.


## 8.5 야구장 다이어그램 표시 원칙

경기 화면 중앙의 야구장 다이어그램은 단순 배경 이미지가 아니라 현재 상황을 읽는 핵심 정보 패널로 사용한다.

### 수비팀 표시

수비팀은 각 포지션의 실제 수비 위치에 맞춰 표시한다.

표시 형식:

```text
포지션 약자 + 선수 이름
```

예:

```text
CF 김OO
SS 최OO
P 임OO
C 강OO
```

사진이나 초상 썸네일은 기본 경기 화면에 사용하지 않는다.

정보량이 많은 경기 UI의 특성상, 기본 화면은 **포지션 약자 + 이름** 중심으로 유지하는 것을 원칙으로 한다.

### 공격팀 표시

공격팀은 수비수처럼 전원을 표시하지 않는다.

현재 경기 상황에 직접 관련된 선수만 표시한다.

표시 대상:

- 현재 타석의 타자
- 1루 주자
- 2루 주자
- 3루 주자

현재 타자는 좌측 정보 패널 또는 상단 주요 정보 영역에서 별도로 강조한다.

베이스에 주자가 있을 경우, 해당 베이스 위치에 주자 정보를 표시한다.

예:

```text
[주자]
이OO
주루 78
```

### 주자 정보

주자가 베이스에 있을 경우 이름과 함께 **주루 능력치**를 표시한다.

이는 다음 판단에 직접 활용된다.

- 도루 시도
- 대주자 교체
- 단타 / 장타 시 추가 진루 기대
- 태그업 판단
- 번트 후 진루 기대

주루 능력은 `주루 78`처럼 직관적으로 표시한다.

필요하다면 축약형:

```text
SPD 78
```

또는

```text
주루 78
```

중 하나를 UI 통일 규칙에 따라 선택할 수 있다.

---

## 8.6 기본 정보와 상세 정보 분리

경기 화면 기본 정보는 가능한 한 간단하게 유지한다.

기본 노출:

- 수비수: 포지션 약자 + 이름
- 현재 타자: 이름 / 타순 / 주요 정보
- 베이스 주자: 이름 + 주루 능력
- 투수: 이름 + 투수 핵심 정보
- 점수 / 이닝 / 카운트 / 아웃 / 주자 상황

세부 정보는 클릭 또는 호버로 확인한다.

예:

```text
이OO
1루 주자

주루 78
도루 72
컨디션 좋음
피로 18
오늘 2타수 1안타
```

또는:

```text
SS 최OO

수비 74
송구 68
컨디션 보통
오늘 경기 3타수 1안타
```

기본 화면은 직관성을 우선하고, 상세 정보는 상호작용을 통해 확인하는 구조를 사용한다.

---

## 8.7 수비 / 주자 UI 활용 원칙

야구장 다이어그램은 단순 시각 요소가 아니라 전술 판단을 돕는 화면이어야 한다.

플레이어는 이 화면을 통해 다음을 빠르게 읽을 수 있어야 한다.

- 현재 수비 배치
- 어느 베이스에 주자가 있는가
- 현재 주자의 주루 능력은 어느 정도인가
- 현재 타석의 공격 선택에 어떤 리스크와 기대가 있는가

즉 경기 화면의 핵심 목적은:

> 현재 상황을 한눈에 파악하고, 다음 선택을 빠르게 결정하게 하는 것

이다.

# 9. 경기 결과 화면

경기가 끝나면 즉시 플레이어에게 필요한 정보를 요약한다.

예:

```text
경기 종료
```

# 13. 리그 화면

리그 전체 정보를 확인한다.

주요 탭:

```text
순위
개인 기록
선수 DB
수상 경쟁
유망주
뉴스
역사
```

플레이어가 구단 운영자가 아니기 때문에 지나치게 상세한 구단 재정 정보는 우선순위를 낮춘다.

## 13.1 전체 선수 DB

`리그 > 선수 DB`에서 현재 세이브에 존재하는 선수들을 검색하고 조회할 수 있도록 한다.

별도의 최상위 `선수 DB` 메뉴를 추가하지 않고 리그 메뉴의 하위 기능으로 두는 것을 기본으로 한다.

목록 예:

```text
[선수명 검색]

구단       [전체 ▼]
포지션     [전체 ▼]
1군/2군    [전체 ▼]
선수 상태  [현역 ▼]

이름       팀       POS   나이   상태       시즌 성적
김OO       두산     SS     24    1군 주전   .302 / 17HR
박OO       LG       SP     27    선발       8승 / 2.91
이OO       한화     CF     20    2군       .281 / 6HR
```

기본 검색 / 필터:

- 선수명
- 구단
- 포지션
- 나이
- 투수 / 야수
- 1군 / 2군
- 신인 / 유망주 / 베테랑
- 현역 / 은퇴 / 전체

목록은 이름, 나이, 주요 기록 등 필요한 열을 기준으로 정렬할 수 있다.

장기 세이브에서 기본 목록은 현역 중심으로 보여주되 은퇴 선수도 검색할 수 있어야 한다.

## 13.2 공통 선수 프로필

선수 DB에서 선수를 선택하면 **공통 선수 프로필 화면**으로 이동한다.

예:

```text
김OO / SS / 두산
24세 / 우투우타

[프로필]
[능력 평가]
[기록]
[커리어]
[계약]
[부상]
[수상]
[국가대표]
[뉴스]
```

프로필 표시 정보 예:

- 이름
- 나이 / 생년월일
- 신장 / 체중
- 출신
- 투타
- 소속팀
- 1군 / 2군 상태
- 주 포지션 / 보조 포지션
- 등번호
- 현재 역할
- 시즌 기록
- 통산 기록
- 계약 / FA 상태
- 부상 이력
- 개인 수상
- 국가대표 경력
- 주요 커리어 사건
- 관련 뉴스
- 영구결번 / 명예의 전당 결과

선수의 상태에 따라 의미 없는 탭은 숨기거나 비활성화할 수 있다.

## 13.3 선수 프로필 능력 공개 규칙

공통 선수 프로필에서도 기존 능력치 공개 규칙을 유지한다.

### 플레이어 자신의 선수

현재 기본 능력을 정확한 숫자로 표시한다.

```text
컨택 72
파워 68
수비 74
```

### NPC 선수

정확한 내부 능력 대신 스카우팅 등급 또는 추정 범위를 표시한다.

```text
컨택 A-
파워 B+
수비 A

스카우팅 신뢰도: 높음
```

또는:

```text
컨택 70~80
파워 60~70
```

### 잠재력

플레이어와 NPC 모두 실제 잠재력 숫자를 표시하지 않는다.

선수 DB는 정보를 편하게 찾아보는 기능이며, 숨겨진 내부 데이터를 해제하는 기능이 아니다.

## 13.4 전역 선수 링크

게임 안에서 표시되는 선수 이름은 가능한 한 클릭 가능한 공통 선수 링크로 취급한다.

예:

```text
경기 화면
상대 투수 박OO 선택
↓
박OO 선수 프로필
```

```text
뉴스
"김OO, 시즌 20호 홈런"
↓
김OO 선택
↓
김OO 선수 프로필
```

연결 대상:

- 경기 화면의 타자 / 투수 / 수비수 / 주자
- 팀 로스터
- 리그 개인 기록
- 유망주 랭킹
- 수상 경쟁
- 드래프트 결과
- 계약 / FA / 트레이드 관련 화면
- 국가대표 명단
- 뉴스 기사
- 명예의 전당
- 커리어 기록

선수 이름을 선택할 때 내부적으로 `player_id`를 전달하여 동일한 공통 프로필 화면을 사용한다.

뒤로 이동하면 가능하면 이전 화면의:

- 검색 조건
- 필터
- 정렬
- 스크롤 위치

를 유지한다.

## 13.5 은퇴 선수 프로필

은퇴 선수도 선수 DB에서 조회할 수 있다.

은퇴 후에는 현재 능력보다 커리어 정보를 우선한다.

예:

- 통산 기록
- 연도별 기록
- 소속팀 이력
- 개인 수상
- 국가대표 경력
- 주요 부상
- 주요 뉴스
- 영구결번
- 명예의 전당

이를 통해 장기 세이브에서 과거의 선수와 리그 역사를 다시 탐색할 수 있도록 한다.

# 26. 능력치 표시 원칙

## 플레이어 자신의 현재 능력

정확한 숫자 표시.

```text
컨택 72
파워 68
```

## 다른 선수 현재 능력

스카우팅 기반 등급 또는 범위.

```text
구위 A-
제구 B
```

또는:

```text
구위 70~80
```

## 실제 잠재력

모든 선수 비공개.

UI에서 정확한 내부 잠재력 숫자는 표시하지 않는다.

# 27. 중요 정보 우선순위

UI는 정보 중요도를 세 단계로 구분한다.

## Priority A — 즉시 보여줘야 하는 정보

- 경기 시작
- 부상
- 계약 선택
- FA 제안
- 1군 콜업 / 말소
- 국가대표 선발
- 병역 선택
- 은퇴 관련 결정

## Priority B — 홈 화면에 요약

- 선수 상태
- 최근 성적

## 34.1 저장 정책

Star Player는 **수동 저장과 자동 저장을 모두 지원한다.**

### 수동 저장

플레이어는 일반적인 게임 진행 중 원하는 시점에 직접 저장할 수 있다.

단, 경기 결과 계산 중이나 상태 적용 중처럼 데이터가 변경되는 중간 단계에서는 저장을 제한할 수 있다.

### 자동 저장

자동 저장은 장기 커리어 데이터 손실을 줄이기 위해 주요 진행 지점에서 수행한다.

기본 자동 저장 시점:

- 경기 종료 후
- 날짜 진행 후
- 시즌의 주요 단계 전환 시
- 계약 / FA 등 중요한 커리어 이벤트 전후
- 드래프트, 콜업, 말소 등 주요 상태 변화 후

자동 저장 빈도가 지나치게 높아 게임 진행을 방해하지 않도록 한다.

### 세이브 슬롯

여러 개의 커리어를 별도로 저장할 수 있다.

하나의 커리어에서도 복수의 수동 저장 슬롯을 사용할 수 있도록 한다.

예:

```text
김OO 커리어

자동 저장
수동 저장 1
수동 저장 2
수동 저장 3
```

하나의 저장 파일만 강제로 사용하는 구조는 피한다.

### 이어하기

메인 메뉴의 `이어하기`는 가장 최근에 저장된 정상 세이브를 자동으로 선택하여 불러온다.

플레이어가 다른 저장 시점을 선택하려면 `불러오기` 메뉴를 사용한다.

### 데이터팩과 세이브

세이브는 커리어 생성 당시 선택한 데이터팩 정보를 함께 기록한다.

진행 중인 커리어는 원본 데이터팩이 나중에 수정되더라도 세이브 내부에 저장된 게임 세계 상태를 우선한다.

따라서 데이터팩 변경이 기존 커리어의:

- 선수 능력
- 로스터
- 계약
- 기록
- 성장
- 부상
- 리그 역사

등을 자동으로 덮어쓰지 않도록 한다.

# 44. UX 검증 기준

- 선택 결과를 바로 이해할 수 있는가?

- 다음에 무엇을 해야 하는지 바로 알 수 있는가?

## 계약

- 여러 제안의 핵심 차이를 빠르게 비교할 수 있는가?

## 장기 플레이

- 메뉴 이동이 반복 플레이에서 피로하지 않은가?
- 불필요한 팝업이 너무 많이 나오지 않는가?

# 46. 해상도 및 화면 대응 기준

Star Player의 공식 지원 해상도는 **2560 × 1440 (QHD)** 과 **1920 × 1080 (FHD)** 두 가지로 한정한다.

두 해상도 모두 16:9 비율이며, 지원 범위를 명확히 제한하여 정보 중심 UI의 완성도와 QA 효율을 높이는 것을 우선한다.

초기 버전에서는 1600 × 900, 1366 × 768, 4K, 울트라와이드 전용 레이아웃 등을 공식 지원 대상으로 포함하지 않는다.

---

## 46.1 공식 지원 해상도

| 구분 | 해상도 | 역할 |
|---|---:|---|
| 개발 / 디자인 기준 | 2560 × 1440 | 전체 정보형 레이아웃 기준 |
| 표준 지원 | 1920 × 1080 | 일반적인 플레이 및 배포 기준 |

공식 QA 역시 위 두 해상도만 대상으로 한다.

---

## 46.2 2560 × 1440 기준

UI 와이어프레임, 화면 배치, 정보량, 패널 구성의 기본 기준은 2560 × 1440으로 한다.

예:

```text
2560 × 1440

┌──────────────────────────────────────────────────────────────┐
│ 상단 상태 바                                                 │
├──────────────┬───────────────────────────────┬───────────────┤
│ 좌측 메뉴    │          메인 콘텐츠          │ 우측 정보     │
│              │                               │ 패널          │
│              │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

QHD에서는 좌측 메뉴, 메인 콘텐츠, 우측 정보 패널을 동시에 표시하는 것을 기본으로 한다.

정보량이 많은 기록, 선수 DB, 구단 DB, 뉴스, 커리어 화면 역시 QHD를 우선 기준으로 설계한다.

---

## 46.3 1920 × 1080 대응

1920 × 1080에서도 QHD와 **동일한 기능**을 사용할 수 있어야 한다.

단순히 전체 UI를 작게 축소하지 않고 다음 요소를 조정한다.

- 좌측 메뉴 폭 축소
- 우측 정보 패널 폭 축소
- 카드 내부 여백 감소
- 카드 간 간격 감소
- 중요도가 낮은 표의 보조 열 일부 숨김
- 긴 텍스트는 줄바꿈 또는 상세 팝업으로 이동
- 필요한 경우 보조 정보 영역을 탭으로 이동
- 세로 스크롤 활용

기능 자체를 삭제하거나 FHD 전용으로 내용을 축소하지 않는다.

예:

```text
QHD
선수 | 나이 | 포지션 | 경기 | AVG | HR | RBI | OPS | WAR

FHD
선수 | 포지션 | 경기 | AVG | HR | OPS | WAR
```

숨겨진 보조 정보는 선수 프로필이나 상세 화면에서 계속 확인할 수 있어야 한다.

---

## 46.4 화면 비율

공식 지원 화면 비율은 **16:9**로 한다.

지원 대상:

```text
2560 × 1440
1920 × 1080
```

16:10, 울트라와이드 및 기타 특수 비율은 초기 공식 지원 범위에서 제외한다.

해당 환경에서 실행 자체가 가능하더라도 별도의 레이아웃 최적화와 QA를 보장하지 않는다.

---

## 46.5 창 모드

초기 PC 버전에서는 다음 화면 모드를 고려한다.

- 창 모드
- 테두리 없는 창 모드
- 전체 화면

단, UI의 공식 레이아웃 및 QA 기준은 2560 × 1440과 1920 × 1080을 기준으로 한다.

창 크기를 임의로 너무 작게 줄여 UI가 깨지는 상황까지 공식 대응 범위로 잡지 않는다.

필요하다면 최소 창 크기를 제한한다.

---

## 46.6 해상도별 QA 기준

주요 UI 화면은 반드시 다음 두 환경에서 확인한다.

```text
2560 × 1440
1920 × 1080
```

확인 항목:

- 텍스트 잘림
- 버튼 겹침
- 표 열 잘림
- 스크롤 동작
- 팝업 화면 이탈
- 뉴스 텍스트 줄바꿈
- 선수 및 구단 이름 길이
- 숫자 자리수 증가
- 경기장 다이어그램 배치
- 선수 DB 및 구단 DB 테이블
- 이벤트 팝업
- 저장 / 불러오기 화면

두 해상도에서 주요 기능의 접근성과 정보 의미가 동일하게 유지되어야 한다.

---

## 46.7 Prototype 단계 적용

### Prototype 1

2560 × 1440 기준의 임시 UI를 우선 구현한다.

### Prototype 2

2560 × 1440과 1920 × 1080 두 환경에서 핵심 플레이 UX를 검증한다.

### Prototype 3

두 해상도 모두 주요 메뉴, 기록표, 경기 화면, 시즌 진행 화면을 QA한다.

### Alpha

두 해상도의 전체 주요 화면을 검증한다.

### Polish

2560 × 1440과 1920 × 1080에서 최종 UI QA를 진행한다.

추가 해상도 지원을 위해 별도 작업 범위를 확대하지 않는다.

---

## 46.8 최종 원칙

```text
공식 지원 해상도

2560 × 1440 (QHD)
1920 × 1080 (FHD)
```

**QHD를 디자인 기준으로 사용하고, FHD에서도 모든 핵심 기능을 동일하게 제공한다.**

그 외 해상도는 초기 버전의 공식 지원 및 QA 범위에서 제외한다.

# 47. Codex 로드맵 작성 시 UI 원칙

Codex가 개발 로드맵을 만들 때 다음 원칙을 따른다.

1. UI를 별도의 마지막 작업으로 몰아넣지 않는다.
2. 각 Prototype에 필요한 최소 UI를 해당 단계와 함께 구현한다.
3. Prototype 1에서는 임시 UI를 허용한다.
4. Prototype 2에서 핵심 사용자 흐름을 검증한다.
5. Prototype 3에서 주요 메뉴 구조를 완성한다.
6. Alpha 전에는 최종 비주얼 디자인에 과도하게 투자하지 않는다.
7. UI 코드는 게임 핵심 로직과 분리한다.
8. 공통 컴포넌트는 재사용 가능하도록 설계한다.
9. 데이터가 없는 상태와 오류 상태도 UI 테스트에 포함한다.
10. 기능 추가 시 해당 기능을 확인하고 조작할 최소 UI를 함께 구현한다.
11. 기본 UI는 2560 × 1440을 기준으로 설계하되 1920 × 1080에서 동일 기능을 사용할 수 있어야 한다.
12. Prototype 2부터 2560 × 1440과 1920 × 1080 두 해상도를 함께 검증하며, 그 외 해상도 QA는 초기 범위에 포함하지 않는다.
13. 선수 DB와 공통 선수 프로필은 `player_id`를 단일 식별자로 사용한다.
14. 경기, 뉴스, 로스터, 기록, 랭킹 등에서 표시되는 선수 이름은 가능한 한 재사용 가능한 `PlayerLink`를 통해 동일 프로필로 연결한다.
15. 선수 프로필 이동 후 뒤로 돌아갈 때 검색 조건, 필터, 정렬, 스크롤 위치를 가능한 한 유지한다.
16. 선수 DB에서도 NPC의 정확한 내부 능력과 실제 잠재력을 추가로 노출하지 않는다.

이다.

# 50. 아마추어·신인 공급 시스템 UI

장기 세이브의 신인 생성 과정을 플레이어가 이해할 수 있도록 아마추어·신인 공급 시스템과 연결된 UI를 제공한다.

이 UI의 목적은 학교를 직접 운영하는 것이 아니라:

> 올해 어떤 신인들이 어떤 학교와 경로에서 등장했는가?

를 확인하는 것이다.

---

## 50.1 접근 경로

기본 접근:

```text
리그
↓
신인 / 드래프트
```

하위 탭 예:

```text
[신인 풀]
[고교]
[대학]
[해외파]
[드래프트 전망]
[역대 드래프트]
```

---

## 50.2 신인 풀 화면

해당 연도 드래프트 대상 선수를 확인한다.

예:

```text
2032 신인 드래프트 풀

[이름 검색]

출신      [전체 ▼]
학교      [전체 ▼]
포지션    [전체 ▼]
지역      [전체 ▼]

이름      POS   나이   출신팀        현재 평가   예상 지명
김OO      SS    18     OO고          B+          1~2R
박OO      SP    22     OO대학교      A-          1R
이OO      CF    24     일본 OO Team  B           3~5R
```

선수 이름을 클릭하면 기존 공통 선수 프로필 또는 신인용 프로필 화면으로 이동한다.

---

## 50.3 신인 프로필

드래프트 전 선수 프로필에서는 프로 선수와 다른 정보 우선순위를 사용한다.

예:

```text
김OO
18세 / SS
OO고등학교
우투우타

현재 평가
수비형 유격수

타격     B
파워     C+
수비     A-
송구     A
주루     B+

예상 성장
높음

평가 신뢰도
보통
```

표시 가능 정보:

- 이름
- 나이
- 출신 학교 / 팀
- 지역
- 포지션
- 투타
- 신장 / 체중
- 현재 스카우팅 평가
- 주요 장점
- 주요 약점
- 평가 신뢰도
- 예상 드래프트 범위
- 아마추어 주요 기록 또는 요약

실제 잠재력 숫자는 표시하지 않는다.

---

## 50.4 출신 학교 표시

신인 및 프로 선수 프로필에서 출신 학교를 확인할 수 있다.

예:

```text
출신

OO고등학교
→ OO대학교
```

해외파:

```text
출신

OO고등학교
→ 일본 OO Team
→ KBO 진출
```

학교명 또는 팀명을 선택하면 간단한 출신팀 정보 패널을 열 수 있다.

---

## 50.5 학교 / 팀 정보 패널

학교와 아마추어 팀은 구단 운영 화면 수준의 복잡한 UI를 제공하지 않는다.

기본 정보 예:

```text
OO고등학교

지역
서울

구분
고교 야구부

현재 명성
높음

스카우트 노출
매우 높음

최근 5년 프로 지명
11명

주요 출신 프로 선수
김OO
박OO
이OO
```

세부 내부 수치 대신 등급 또는 상태 표현을 우선한다.

---

## 50.6 학교별 선수 검색

신인 풀에서 학교명을 클릭하면 해당 학교 출신 선수를 필터링할 수 있다.

예:

```text
OO고등학교 출신

현역 프로
김OO / SS / 두산
박OO / SP / LG

올해 드래프트 대상
이OO / CF

은퇴 선수
최OO / 2B
```

이를 통해 장기 세이브에서 특정 학교가 어떤 선수들을 배출했는지 확인할 수 있다.

---

## 50.7 드래프트 전망 UI

드래프트 전에는 신인들의 실제 잠재력이나 정확한 내부 순위를 공개하지 않는다.

대신:

```text
예상 상위 지명 후보

1. 김OO / SP / OO고
   현재 평가 A-
   예상 지명 1R
   평가 신뢰도 높음

2. 박OO / SS / OO대학교
   현재 평가 B+
   예상 지명 1~2R
   평가 신뢰도 보통
```

처럼 보여준다.

예상 지명 순위는 실제 AI 구단의 최종 선택과 다를 수 있다.

---

## 50.8 드래프트 결과 UI

드래프트가 끝나면 실제 지명 결과를 기록한다.

예:

```text
2032 KBO 신인 드래프트

1R 1순위
김OO / SP / OO고
→ 한화

1R 2순위
박OO / SS / OO대학교
→ 두산
```

선수와 학교 이름 모두 선택 가능하게 한다.

선수명:
→ 공통 선수 프로필

학교명:
→ 학교 정보 패널

---

## 50.9 선수 DB와 연동

전체 선수 DB에 `출신` 관련 필터를 추가할 수 있다.

예:

```text
출신 학교
OO고등학교

출신 유형
고졸 / 대졸 / 해외파
```

장기 세이브에서는:

```text
OO고 출신 KBO 선수
총 37명

현역 14명
은퇴 23명
```

처럼 세이브 내 출신 학교 역사를 확인할 수 있다.

---

## 50.10 실제 학교 데이터와 가상 선수

UI에서는 실제 학교 또는 팀 데이터와 자동 생성 선수를 자연스럽게 연결한다.

예:

```text
2038 신인드래프트

김OO / OO고
박OO / OO대학교
이OO / 일본 OO Team
```

학교와 팀은 데이터팩에서 가져오지만 미래 선수는 세이브 내부에서 생성된 가상 선수다.

실제 선수와 자동 생성 선수를 UI에서 특별히 다른 색상으로 구분할 필요는 없다.

필요한 경우 프로필의 데이터 출처 정보에서만 확인할 수 있도록 한다.

---

## 50.11 Prototype 적용 시점

### Prototype 1~2

아마추어 UI 구현 불필요.

### Prototype 3

드래프트 시스템 개발 전까지는 제외 가능.

### 장기 시즌 / Draft 구현 단계

최소 구현:

- 신인 자동 생성
- 출신 학교 / 팀 표시
- 신인 풀 목록
- 드래프트 결과
- 선수 프로필 연결

### 이후 확장

- 학교 정보 패널
- 학교별 출신 선수 검색
- 학교 명성 변화
- 최근 프로 지명 기록
- 드래프트 전망
- 아마추어 스카우팅 UI

---

## 50.12 UI 원칙

1. 학교 운영 게임처럼 복잡하게 만들지 않는다.
2. 아마추어 시스템은 신인 생성과 드래프트의 현실감을 높이는 역할에 집중한다.
3. 신인 선수의 실제 잠재력은 공개하지 않는다.
4. 학교 명성도 숫자보다 등급 또는 설명형 표현을 우선한다.
5. 선수 이름은 기존 공통 선수 프로필과 연결한다.
6. 학교 또는 팀 이름은 간단한 정보 패널과 연결할 수 있다.
7. 실제 학교 데이터가 없는 가상 데이터팩에서도 동일한 UI가 작동해야 한다.
8. 해외팀은 출신 이력용으로 표시하며 해외 리그 순위나 로스터 화면까지 확장하지 않는다.

# 51. 육성선수 UI

육성선수는 별도의 출신 카테고리 화면으로 분리하지 않는다.

UI에서는 선수의 **원래 출신**과 **프로 입단 경로 / 현재 선수 신분**을 각각 표시한다.

예:

```text
김OO / SS / 두산

출신
OO고등학교

프로 입단
2032 신인드래프트 미지명
2033 두산 육성선수 계약

현재 신분
정식선수
```

---

## 51.1 신인 프로필 표시

드래프트 미지명 선수는 신인 프로필에서 결과를 확인할 수 있다.

예:

```text
김OO / SS / OO고

2032 KBO 신인드래프트
미지명

향후 진로
대학 진학 검토
육성선수 계약 가능성
기타 진로
```

게임 엔진이 진로를 확정하기 전에는 가능한 선택지나 상태만 보여준다.

---

## 51.2 육성선수 상태 표시

육성선수 계약 후 프로필에는 현재 신분을 명확하게 표시한다.

예:

```text
현재 신분
육성선수

소속
두산

현재 레벨
2군

입단
2033.01.15

정식선수 전환
아직 없음
```

`육성선수`와 `2군`은 서로 다른 개념이므로 UI에서도 가능하면 분리해서 표시한다.

```text
등록 신분: 육성선수
소속 레벨: 2군
```

---

## 51.3 정식선수 전환 이벤트

육성선수가 정식선수로 전환되면 주요 커리어 이벤트로 표시한다.

예:

```text
정식선수 전환

김OO 선수가 육성선수 신분에서
정식선수로 전환되었습니다.

2034.05.12
```

이 이벤트는:

- 선수 프로필
- 커리어 타임라인
- 팀 로스터 변경
- 뉴스

등에 연결할 수 있다.

---

## 51.4 선수 DB 필터

전체 선수 DB에는 필요할 경우 선수 신분 필터를 제공한다.

예:

```text
선수 신분
[전체 ▼]

전체
정식선수
육성선수
방출
은퇴
```

출신 필터와 선수 신분 필터는 별개로 취급한다.

예:

```text
출신 유형: 고졸
선수 신분: 육성선수
```

처럼 동시에 검색할 수 있다.

---

## 51.5 커리어 타임라인

선수 프로필의 커리어 탭에서는 육성선수 경로를 시간 순서대로 표시한다.

예:

```text
2032
OO고등학교 졸업

2032
KBO 신인드래프트 미지명

2033
두산 육성선수 입단

2034
정식선수 전환

2035
1군 데뷔
```

육성선수 경력이 있는 스타 선수라면 이 이력 자체가 중요한 커리어 스토리가 될 수 있다.

---

## 51.6 UI 원칙

1. 육성선수를 별도 출신 유형처럼 표시하지 않는다.
2. `출신`과 `프로 입단 경로`를 분리해서 보여준다.
3. `육성선수 신분`과 `1군 / 2군 소속 레벨`도 분리해서 보여준다.
4. 정식선수 전환일과 방출일은 커리어 타임라인에 기록한다.
5. 선수 DB에서 육성선수만 필터링할 수 있도록 한다.
6. 육성선수라는 이유로 잠재력 또는 정확한 내부 능력치를 추가 공개하지 않는다.
7. 선수명은 기존 공통 선수 프로필 시스템을 그대로 사용한다.

# 52. 구단 DB 및 공통 구단 프로필 UI

선수 DB와 동일하게 KBO 구단도 공통 프로필 화면을 제공한다.

기본 접근:

```text
리그
↓
구단
↓
구단 선택
```

리그 화면에서 구단명을 선택하면 해당 구단의 공통 프로필을 연다.

---

## 52.1 구단 목록

기본 예:

```text
KBO 구단

구단        현재 순위   시즌 성적      최근 우승
두산        3위         42-31-2       2041
LG          1위         48-26-1       2043
삼성        5위         37-38-0       2037
```

구단명은 클릭 가능한 링크로 표시한다.

필요 시:

- 현재 순위
- 시즌 승률
- 최근 10경기
- 최근 우승
- 한국시리즈 우승 횟수

등을 목록 열로 표시할 수 있다.

---

## 52.2 공통 구단 프로필

구단 프로필의 기본 탭:

```text
[개요]
[역사]
[시즌]
[로스터]
[기록]
[수상]
[영구결번]
```

예:

```text
두산 베어스

서울 / 잠실야구장

현재 시즌
42승 31패 2무
3위

한국시리즈 우승
8회

한국시리즈 준우승
6회

정규시즌 1위
7회

최근 우승
2041
```

구단 로고가 존재할 경우 프로필 헤더에 표시할 수 있다.

---

## 52.3 구단 개요

개요 탭에서는 가장 중요한 정보를 한 화면에서 확인한다.

권장 정보:

- 구단명
- 구단 로고
- 연고지
- 홈구장
- 창단연도
- 현재 감독
- 현재 순위
- 시즌 승 / 패 / 무
- 한국시리즈 우승 횟수
- 최근 우승
- 최근 포스트시즌 진출
- 현재 핵심 선수
- 다음 경기

장기 역사 정보와 현재 시즌 정보가 섞여 혼란스럽지 않도록 영역을 분리한다.

---

## 52.4 구단 역사

역사 탭에서는 연도별 시즌 결과를 시간 순으로 보여준다.

예:

```text
연도   정규순위   성적        포스트시즌      결과
2043   1위       87-55-2     한국시리즈      우승
2042   3위       78-64-2     플레이오프      탈락
2041   1위       90-52-2     한국시리즈      우승
2040   6위       70-72-2     -               -
```

필터 예:

```text
[전체]
[우승 시즌]
[포스트시즌]
[최근 10년]
```

우승 시즌은 시각적으로 쉽게 식별할 수 있도록 아이콘이나 강조 표시를 사용할 수 있다.

---

## 52.5 우승 및 포스트시즌 기록

개요의 `한국시리즈 우승 8회` 같은 요약 정보를 선택하면 세부 목록을 열 수 있다.

예:

```text
한국시리즈 우승 8회

2029
2034
2041
2043
...
```

같은 방식으로:

- 준우승
- 정규시즌 1위
- 포스트시즌 진출

기록을 확인할 수 있다.

집계 숫자와 실제 연도별 기록은 동일한 데이터에서 생성하여 서로 불일치하지 않도록 한다.

---

## 52.6 프랜차이즈 기록

기록 탭은 해당 구단 역사에서 기록한 선수 순위를 보여준다.

예:

```text
구단 통산 홈런

1. 김OO   312
2. 박OO   288
3. 이OO   251
```

카테고리 예:

```text
[안타]
[홈런]
[타점]
[도루]
[WAR]
[승]
[세이브]
[탈삼진]
```

선수 이름 선택 시 공통 선수 프로필로 이동한다.

---

## 52.7 주요 선수

구단 프로필에서는 현재 및 역대 주요 선수를 확인할 수 있다.

예:

```text
현재 핵심 선수
김OO / SS
박OO / SP

역대 주요 선수
이OO / RF
최OO / SP

프랜차이즈 스타
한OO / C
```

선수 사진을 반드시 요구하지 않는다.

기본 표시는 선수 이름, 포지션, 해당 구단에서의 주요 기록 중심으로 구성한다.

---

## 52.8 수상 기록

구단에서 배출한 주요 수상을 확인할 수 있다.

예:

```text
MVP

2045 김OO
2038 박OO
2031 이OO
```

필요한 경우:

- MVP
- 신인왕
- 골든글러브
- 주요 개인 타이틀

등으로 구분한다.

---

## 52.9 영구결번

기존 영구결번 시스템을 구단 프로필에 직접 연결한다.

예:

```text
영구결번

7
김OO
지정: 2040

18
박OO
지정: 2047
```

선수 이름을 선택하면 해당 선수 프로필로 이동한다.

---

## 52.10 현재 로스터

로스터 탭에서는 다음 필터를 제공할 수 있다.

```text
[1군]
[2군]
[육성선수]
[부상]
[군 복무]
```

목록 예:

```text
이름      POS   나이   신분       현재 역할
김OO      SS    24     정식선수   주전
박OO      SP    29     정식선수   선발
이OO      CF    20     육성선수   2군
```

선수 선택 시 공통 선수 프로필로 이동한다.

---

## 52.11 전역 구단 링크

게임 내에서 구단명이 표시되는 주요 위치는 공통 구단 프로필과 연결한다.

예:

```text
순위표
두산
↓
두산 구단 프로필
```

```text
선수 프로필
소속팀: LG
↓
LG 구단 프로필
```

```text
뉴스
"삼성, 한국시리즈 우승"
↓
삼성 구단 프로필
```

대상 화면:

- 리그 순위표
- 일정
- 경기 결과
- 선수 프로필
- FA
- 트레이드
- 드래프트
- 뉴스
- 포스트시즌
- 기록 화면

---

## 52.12 뒤로가기 상태 유지

구단 프로필에서 이전 화면으로 돌아갈 때:

- 리그 순위의 스크롤 위치
- 선택한 시즌
- 역사 필터
- 기록 카테고리
- 로스터 필터

를 가능한 한 유지한다.

선수 DB와 동일한 탐색 경험을 제공한다.

---

## 52.13 해상도 대응

QHD에서는:

```text
구단 헤더
+
왼쪽 주요 정보
+
중앙 시즌 / 역사
+
오른쪽 최근 뉴스 / 핵심 선수
```

구성이 가능하다.

FHD에서는 필요에 따라 오른쪽 보조 패널의 폭을 줄이거나 일부 보조 정보를 탭 내부로 이동한다.

구단 역사와 기록 표는 텍스트를 지나치게 축소하지 않고:

- 불필요한 열 숨김
- 가로 스크롤
- 세부 팝업
- 탭 분리

등으로 대응한다.

---

## 52.14 Prototype 적용 시점

### Prototype 1~2

구단 프로필 구현 불필요.

### Prototype 3

최소 구현:

- 구단명
- 현재 시즌 성적
- 현재 로스터
- 현재 순위

### 장기 시즌 구현 단계

추가:

- 연도별 시즌 역사
- 우승 / 준우승 집계
- 포스트시즌 기록
- 구단 통산 기록

### Alpha 이후

추가:

- 프랜차이즈 기록
- 역대 주요 선수
- 수상 기록
- 영구결번
- 관련 뉴스
- 화면 시각적 완성도 개선

---

## 52.15 UI 원칙

1. 구단 프로필은 구단 운영 화면이 아니다.
2. 현재 시즌과 구단의 장기 역사를 함께 보여준다.
3. 우승 횟수와 연도별 우승 기록은 동일 데이터에서 계산한다.
4. 선수명은 공통 선수 프로필과 연결한다.
5. 구단명은 어디서 선택하더라도 동일한 공통 구단 프로필로 이동한다.
6. 구단 정보는 team_id를 기준으로 연결한다.
7. 실제 데이터팩의 과거 역사와 세이브 이후 역사를 하나의 연속된 역사처럼 표시한다.
8. 1군 / 2군 / 육성선수 등 선수 신분 정보를 기존 선수 시스템과 동일하게 사용한다.
9. 영구결번 및 프랜차이즈 기록을 기존 커리어 시스템과 연결한다.
10. 장기 세이브에서 구단 프로필이 리그 역사를 탐색하는 핵심 화면 중 하나가 되도록 한다.
