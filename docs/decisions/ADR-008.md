## Decisions

### FC-D1 — Neutral cohort `neutral-mixed-v1`

1. Inputs: every player rating 50 (neutral), strategy Normal / Balanced (FC-D3), neutral batter zone tendency, Framing 50, GameCalling 50, PitcherControl 50; deterministic construction; a handedness layout declared before any run. The approved design is the proposal's recommended one (all batters bat right; starting rotation 3 RHP : 4 LHP; within one game every PA has the same handedness relation). The concrete instance (player ids, `InputsHash`) is frozen in the Final Execution Freeze.
2. Handedness evaluation weights (pre-declared, fixed): **same_hand 3/7, opposite_hand 4/7.**
3. Official statistics:
   - **F1** = pre-weighted standardization of the per-stratum strikeout rate: `F1_std = (3/7 × SO_S/PA_S) + (4/7 × SO_O/PA_O)`.
   - **F8** = pre-weighted standardization of the per-stratum swinging-strike rate: `F8_std = (3/7 × SwStr_S/Sw_S) + (4/7 × SwStr_O/Sw_O)` (the denominator is swings, not PA).
   - **F6, F7** = observed aggregate over the declared cohort (Σ numerator / Σ denominator).
   - S = same_hand stratum, O = opposite_hand stratum; the stratum of a game is a property of the game (its starters' handedness), not of an observed rate.
4. Integer ppm: computed once from the exact counts, **no intermediate rounding**, half-up: `ppm = floor((2·10^6·(3·N_S·D_O + 4·N_O·D_S) + 7·D_S·D_O) / (14·D_S·D_O))`, checked 64-bit (or wider) arithmetic.
5. The 3/7 share of games and the observed shares of PA, pitches and swings may differ; the weights apply to each metric's own denominator and do not assume that the observed shares equal 3/7.
6. The arithmetic mean of the handedness factors being 1.0 ((3 × 1.04 + 4 × 0.97) / 7) is **not** a claim that the game result is fully neutral (normalization is non-linear; see proposal §3.2).
7. Variance of a standardized estimator (diagnostic): it combines the two strata separately, `w_S²·Var(p̂_S) + w_O²·Var(p̂_O)`, and each stratum's variance is estimated with **games as clusters** (game-level dependence). A pooled Wilson interval of the summed counts is **not** applied to F1 / F8. The exact estimator is specified and tested in F-C2. The verdict itself follows FC-D6 (point estimate after the minimum sample is met).
8. **F1 cohort conflict (proposal C-1) — resolved by the owner:** the official F1 cohort is `neutral-mixed-v1` with the standardization above. The tuning description of F1 ("strikeouts per plate appearance, league average, neutral inputs …") and the fact that the committed harness code recommends `VirtualLeague` for F1 are both preserved as history; the tuning JSON is **not** changed; F-C2 changes the harness evaluation definition.

### FC-D2 — Virtual league cohort `virtual-league-v1`

1. Design id `virtual-league-v1`; rating value set **`35, 40, 45, 50, 50, 50, 55, 60, 65`** (mean 50, symmetric about 50).
2. Conditions: mean 50; symmetric distribution; no perfect correlation between abilities; deterministic player and team placement; explicit batter and pitcher handedness; home / away balance; a starting-pitcher rotation; versioned input with a fixed input hash.
3. Official cohort for **F2, F3, F4 and F5** (observed aggregate, proposal method A).
4. Basis: the proposal's recommended rating rotation and team design (§4: cyclic shifts per ability, mirror teams, rotated batting order, 7-man rotation with the same 3 RHP : 4 LHP structure, each handedness group averaging 50).
5. The concrete execution instance (player ids, handedness composition as built, final input-file hash, cohort `InputsHash`) is validated in F-C2 and frozen before F-C3 (Final Execution Freeze).
6. No other rating distribution may be introduced.

### FC-D3 — Calibration strategy `normal-balanced-v1`

Batter approach Normal, `PitchIntent` Balanced, no `Take`, no substitution. No separate RNG for strategy choice. The strategy does not change during an official statistic measurement. The dominant-strategy check (FC-D4) and the calibration (FC-D6 / FC-D7) are separate runs.

### FC-D4 — Dominant-strategy check (48 cells)

1. Matrix: 4 batter strategies (Normal, Patient, Aggressive, TakeFirst) × 3 pitcher strategies (Balanced, Attack, Careful) × 2 handedness conditions (same, opposite) × 2 `CalledPitchMode` (Automated, NonAutomated) = **48 cells**, as tabulated in proposal §6.6 (cell ids, cohorts `neutral-v1` / `neutral-opp-v1`, policy ids, competition keys).
2. Statistical policy: **δ = 0.05 runs per half-inning** (innings 1-8, cell-mean difference); **α = 0.05** (one-sided); **target power 0.8**; variance estimated at the **game** level (game = cluster; game observation = mean runs of its 16 half-innings of innings 1-8); unpaired Welch comparison; **Holm-adjusted non-superiority test** (H0 "σ beats every (τ, column) by at least δ"); **dominance (superiority) uses the intersection-union (IUT) structure** (every one-sided lower bound > 0); a paired test is **not** used for comparisons without a real matched design.
3. Payoff direction, comparison columns and the precedence rule follow proposal §6.4 / §6.7 (offence: runs scored per half-inning; defence: minus runs allowed; dominance takes precedence when both conditions hold; the union of seven false-dominance detections is not further adjusted, because that error direction fails the gate).
4. Verdicts: `DOMINANCE_DETECTED`, `NO_DOMINANCE_SUPPORTED`, `INCONCLUSIVE`, `NOT_EVALUATED`. **Failing to find dominance for lack of evidence is never an automatic PASS**; the check passes only when both sides are `NO_DOMINANCE_SUPPORTED`.
5. **F-C2 required verification — assumption A-1 (proposal §6.7):** with both teams using the same policy object, the batter-strategy and pitcher-strategy payoffs can be compared one-sidedly (policy state-free, no score or inning dependence, nothing carried across half-innings, no substitution). If A-1 does not hold, the implementation structure is corrected **before** the official matrix run and the owner is told.
6. Seed / GameId: the same seed with a different GameId is a different RNG path (the RNG context key is the GameId). A different GameId is **not** a mathematical proof of statistical independence; independence across games and cells is a design assumption of this check.
7. Frozen later (Final Execution Freeze, after the dry run): official sample size per cell, execution cap, the exact seed manifest, the basis of the power estimate (the proposal's σ_g pilot rule and its single pre-declared extension rule for `INCONCLUSIVE` are candidates for this freeze, not approved values).

### FC-D5 — Seed manifest (generation policy)

1. Run families: `fc2-dry`, `fc3-cal`, `fc3-int`, `fc3-dom`.
2. Policy: a unique competition key per family (and per stratum / cell); deterministic GameId; the RNG context binding is kept (context = GameId); pre-declared seed order; the seed file's SHA-256 is fixed; a failed seed is never excluded or replaced; seeds are never changed after seeing results; the manifest is replayable; the official Git SHA is fixed before a run.
3. Calibration runs in **pre-declared blocks**; when the cumulative 100,000 PA is reached, the games of the block in progress are still completed.
4. Block size and the exact seed ranges are fixed right before F-C3 to match the approved cohort design (`FINAL_EXECUTION_FREEZE_PENDING`; the proposal's §7.2 / §7.5 ranges, caps and 7 / 63-game blocks are candidates).
5. No official seed file is created or activated by this ADR.

### FC-D6 — Minimum sample

1. Constants: **k = 0.25, DEFF = 2, z = 1.959964.**
2. Formula: `n_min = ceil(DEFF × z² × p(1-p) / (k × h)²)`, p = midpoint of the pre-declared target interval, h = its half-width; the ceiling is applied **once**, at the end.
3. Approved minimum denominators (re-computed 2026-10-17 from `virtual_tuning_v4.json`; all eight equal the table):

   | Metric | Denominator | Minimum |
   |---|---|---:|
   | F1 | PA | 8,158 |
   | F2 | PA | 15,297 |
   | F3 | PA | 38,239 |
   | F4 | PA | 29,964 |
   | F5 | AB − SO − HR + SF | 40,906 |
   | F6 | located pitches | 3,043 |
   | F7 | pitches − HBP pitches | 4,795 |
   | F8 | swings | 6,229 |

4. Per-stratum minimums (F1 / F8 must meet both the total and each stratum): **F1 PA_S ≥ 3,497, PA_O ≥ 4,662; F8 Sw_S ≥ 2,670, Sw_O ≥ 3,560** (`ceil(3/7 × n_min)`, `ceil(4/7 × n_min)`). A missed stratum minimum is `INSUFFICIENT_SAMPLE`.
5. DEFF = 2 is an approved **design assumption**, not a constant verified on observed data. These thresholds alone do not guarantee an error rate of the official verdict.
6. Official PASS / FAIL: after the approved minimum sample is met, the point estimate is compared with the declared interval (bounds inclusive). Wilson intervals stay diagnostic.

### FC-D7 — Calibration execution (four strata) and integration

| Stratum | Cohort | Mode (rules profile) | Official metrics |
|---|---|---|---|
| L1 | `neutral-mixed-v1` | Automated (`test-pzl-automated`) | F1, F6, F7, F8 |
| L2 | `neutral-mixed-v1` | NonAutomated (`test-pzl-non-automated`) | F1, F6, F7, F8 |
| L3 | `virtual-league-v1` | Automated (`test-pzl-automated`) | F2, F3, F4, F5 |
| L4 | `virtual-league-v1` | NonAutomated (`test-pzl-non-automated`) | F2, F3, F4, F5 |

1. Each stratum runs **≥ 100,000 PA**; the minimum total is 400,000 PA (the block rule can make it larger).
2. Integration: **100 complete games per called-pitch mode** (`fc3-int`); its metrics are diagnostic.
3. Strata are never pooled into an official PASS; a failed stratum is never compensated by another stratum's success.
4. This is an owner-approved gate **stricter** than the ROADMAP minimum (one 100,000-PA calibration and one set of 100 complete games).
5. Fixed run profile (recommended options of proposal §9): `prob-model-v4` / `tuning-virtual-proto-v4`, `player-input-set-v3`, `advancement-policy-v2` only, the two `gamerules-v2` `fictional_test` profiles above (never labelled the 2026 KBO rules), park `pf-sim-neutral` v1, event budget 3,000.

### FC-D8 — Pitch Zone Lite

1. All **12** ROADMAP Pitch Zone Lite clauses stay. Clause 12 is split:
   - **12a** — the current game-RNG boundary is preserved (only `game/*` streams registered; no presentation stream; harness result hashes made without presentation input). **Phase 3 required check.**
   - **12b** — real BCL / LMV features consume no gameplay RNG. **`DEFERRED`** to the phases that implement them: BCL Phases 5, 6 and 28; LMV-A Phases 5 and 28 (their existing ROADMAP tests already require unchanged RNG / event hashes with the features on, off and at every setting).
2. 12b is **never recorded as PASS** in Phase 3.
3. **Owner-approved exception:** missing 12b is not a separate blocking condition of the Phase 3 final gate, **provided** 12a actually passes and the deferral scope, reason (the features do not exist before Phase 5; Phase 5 depends on Phase 4, which depends on Phase 3) and the owning follow-up phases are recorded.
4. Clauses 1-11 and 12a need actual verification evidence (proposal §10 per-clause table).

### FC-D9 — Failure and rerun

1. One or more engine or metrics failures fail that official validation gate.
2. No PASS by re-aggregating without the failed games or seeds.
3. A missed statistical target is reported as FAIL.
4. Too small a sample is `INSUFFICIENT_SAMPLE`; not run or a required contract not met is `NOT_EVALUATED`.
5. After a code or tuning change, the whole official validation is re-run on the new Git SHA and input manifest.
6. Tuning v4 is never edited to fit results; a recalibration is a separate `TuningVersion` judged on a separate holdout validation.

### FC-D10 — Official Mode (F-C2 implementation contract)

Required (all fail-closed): reject unregistered CLI options; reject duplicate options; reject the test seam `--tuning FILE` in an official run; verify the approved model / tuning hashes; allow only approved cohorts and policies; verify the official seed-manifest hash; verify the hash of every consumed input file; verify the Git dirty state; replay every official cohort and policy; record the official run facts in a manifest; keep the technical exit code separate from the statistical gate; preserve reproduction evidence on failure.

Git dirty policy:

| Reject | Allow (exception) |
|---|---|
| a tracked-file change; a staged change; an untracked file other than the protected ones; an ignored file that is not approved | the three protected user files at their exact paths (`TASK.md`, `docs/2023recordRule.pdf`, `docs/2026-official-baseball-rules.pdf`); approved build-output paths |

The protected user files are never inputs of an official validation. Build output must be bound to the approved source SHA and input hashes (proposal §12.1: build at that SHA right before the run and record it). Official Mode is implemented in F-C2; no code changes here.

### FC-D11 — Evidence retention (basic structure)

Raw run output stays in `build/simharness/<run>/` (git-ignored). Version-controlled: the official policy id, the official seed manifests, input / config hashes, model / tuning hashes, the statistic results, success / failure and reproduction evidence, the PZL results, the dominance results and the final report. Large raw logs are not committed. The retention period of raw output is a separate operational decision; existing retained output is never deleted automatically.

### FC-D12 — Phase 3-F final gate

Phase 3-F completes only when all hold: (1) the pre-frozen policy is used; (2) the official seed manifests are used; (3) full `tools/verify.ps1` PASS; (4) the four calibration strata are complete; (5) 100 complete games per mode are complete; (6) every game ends legally; (7) zero engine / metrics failures; (8) BoxScore cross-check PASS; (9) RNG / event hash replay matches; (10) F1-F8 official statistics PASS; (11) dominant-strategy check PASS; (12) the required PZL checks PASS; (13) the explicit deferral of PZL #12b is recorded; (14) the official result report is written; (15) independent review and the owner's final approval. **CLI exit 0 alone never passes the gate.** Passing the 3-F gate does not by itself close the Phase 3 gate (its other Tests / UI / fixture criteria remain).
