# ADR-003 — Event-driven baseball reducer, unverified KBO-oriented profile and independent scoring oracle (Phase 2)

- Status: Proposed — Phase 2 implementation decisions, awaiting GPT Chat / owner review (`검토 대기`).
- Date: 2026-10-10 (amended 2026-10-11: items 23-26, 27-32 after the owner ordered the six OBR differences fixed, and item 33 for C33 / C38)
- Scope: Phase 2 only. No product rule changed; all items are implementation choices inside AGENTS.md invariants (D1, D2).

## Decisions

1. **The reducer checks facts, it never chooses them.** `GameReducer.Apply(state, event)` is pure and input-driven (no RNG, no clock, no I/O). A later resolver (Phase 3) will produce the same events; nothing in the engine must change for that. Probabilistic outcome selection is explicitly out of Phase 2.
2. **D1 is a stage in the state, not a UI convention.** `PaStage` (`Start` / `Decision` / `InSequence`) with the real `PitchCountState`, runners and walk-charge override lives inside `GameState`, so a game resumes inside a plate appearance after a `Take` without replaying the resolved pitch. `Take` is legal only before an approach is chosen and only for ball / called strike / HBP.
3. **One scoring path.** Every play (pitch-ending PA, batted ball, steal, pickoff, balk, WP/PB) goes through `FinishPlay`: validate runner plans → produce `ScoredPlay` evidence and `StatEntry` rows → close the half-inning. Earned runs are reconstructed once per closed half from the `ScoredPlay` list (`EarnedRuns`), never tracked incrementally, so reliever changes and later errors cannot leave stale earned/unearned flags.
4. **Official records are append-only evidence.** Box scores, catcher exposure and battery exposure are projections of `StatEntry` rows (`BoxScoreBuilder`), built once in `Finalize` (a second call returns the same `FinalizedGame`). Exposure is therefore unique by construction, and replaying the event list reproduces it exactly.
5. **GameRules are an immutable snapshot with an honest status.** `GameRuleSnapshot` carries profile ID, version, `KboOrientedUnverified | FictionalTest`, provenance, open items and a SHA-256 content hash; a finished game records both. No official KBO document was supplied, so the KBO-oriented profile is **labelled unverified** and its open items are listed (`docs/game-engine.md` §5). The D2 production-subset certification stays INCOMPLETE; fictional profiles exercise rule-profile behaviour (DH on/off, two-way on/off, extra-inning limit 10/11/none).
6. **Scorer judgement is explicit input, not a guess.** Timing-play runs, sacrifice bunts and error-caused extra bases are flags/causes supplied with the event and validated (rejected when unused or contradictory); the sacrifice fly is rule-derived. Documented simplifications (RBI, earned-run replay convention, W/L/S) live in `docs/game-engine.md` §6.
7. **Independent oracle.** `tests/Fixtures/generator/generate_scripted_games.py` produces both the 100 scripted games and their expected results with its own scorer; hand-computed expectations in the Simulation tests are written from the rules, not read from the engine. Tamper tests prove the comparison can fail. Limit stated: same author, same reading of the document — it cannot certify the documented conventions against the official rules.
8. **Client sees public DTOs only.** `GameDiagnosticsService` has an internal constructor; `ScriptedGameSource`, the JSON readers and `GameReducer` use are internal behind the existing `InternalsVisibleTo` pins; the only public entry is `GameDiagnosticsComposition.CreateFictionalPhase2()`. Architecture and trusted-boundary tests were extended (source scan, reflection surface, IL scan).
9. **Phase 1 collection debt fixed first (2-A).** Public lists in `Ratings`, `Proficiency`, `PlayerStatus`, `DevelopmentProfile` and `Player` are defensive copies exposed through `AsReadOnly()`; `IList` cast mutation throws `NotSupportedException`; mutation tests added. JSON format and visibility policy are unchanged.

## Consequences

- Phase 3 only needs to turn probabilities into `GameEvent`s; it must not bypass `Apply`.
- Phase 4 must define the persistence mapping for `game_states` / `scored_plays` (Phase 2 defines the contract and fixture serialization only; no migration exists).
- The KBO-oriented profile values must be replaced by an evidence-backed, versioned profile before any production career consumes it (D2); existing careers never change.
- `verify.ps1` now records `PHASE_2_VERIFY_LOG.md` and adds G4/E4 (game diagnostics headless/exported), D1 (relative doc links) and D2 (changed files, informational); Phase 0/1 logs are untouched.

## Amendments after the Codex review (2026-10-10, `CHANGES REQUIRED`: High 3, Medium 1, walk-off left on base)

The first-round decisions above stay; these supersede the parts they name.

10. **Outs are classified from the state, not from the input (supersedes the declared-kind part of item 3).** A runner out must declare `OutKind`
    and `Sequence`/`OutAt` where the rules need them, but force status is derived (batter-runner still alive, every base behind occupied by a runner not yet
    out, out made at the base he was forced to) and a disagreeing declaration is rejected. The scorer flag `TimingPlayRuns` is removed: the order of outs
    and runs is data (`Sequence`), required exactly when a third out and a run share a play. One rule (`ThirdOutRule`) decides which runs count for the
    live scorer and for the earned-run replay; voided runs stay visible as `RunVoided` evidence and in no statistic.
11. **An event id belongs to one event (supersedes the idempotency part of item 4).** `GameState.AppliedEvents` keeps receipts (kind + `ef1` SHA-256
    fingerprint of a canonical, order-independent payload text). Same id and content = duplicate, same id other content = `Game.event_id_conflict`.
    The fixture resume contract is events + receipts as JSON; SQLite mapping stays Phase 4.
12. **DH availability and DH state are separate.** `GameRules.DesignatedHitter` / `DhMayBeForfeited` describe the profile, `TeamGameState.DhActive` the
    team now. The KBO-oriented profile keeps forfeiture off (official conditions unverified); the forfeiture transitions are fictional, specified in
    `docs/game-engine.md` section 4 and used only by `test-dh-forfeit` style profiles. No transition can re-create a DH.
13. **A hit by pitch is a dead ball**; extra moves and mishaps on it are rejected with their own codes.
14. **Walk-off left on base** is a profile rule (`CountWalkOffRunnersAsLeftOnBase`, true in all shipped profiles): runners standing on base when the game
    ends are the team's LOB; individual LOB is not recorded. The definition is an unverified simplification.
15. **D2 evidence.** The five KBO pages were read (`docs/game-engine.md` section 5): the extra-innings limit of 11 now has an official KBO source (press
    release 2025-01-22); every other row remains unverified and the Phase 2 Gate stays INCOMPLETE. The record-rule PDF triggered a browser download prompt
    (not retrieved by this work) and its e-book is image-only.
16. **Verification logs.** The first-round logs are kept as `PHASE_2_VERIFY_LOG_initial*.md`; the remediation logs are `PHASE_2_VERIFY_LOG.md` and `_run1`.

## Amendments after the Codex re-review and the owner decisions of 2026-10-11 (`CHANGES REQUIRED`: High batter-runner third out, Medium appeal third out)

17. **A batter-runner is put out BEFORE or AFTER reaching first.** A hit result may now carry a batter move (`From = 0, To = 0`): the batter was safe and was put out
    trying for more. The proof of reaching is the out base (`OutAt` beyond the base the hit gave him), never a boolean; the out is a `Tag`/NonForce out, so
    runs that crossed the plate earlier count, while an out before first base (result `Out`) voids the play's runs. One plate appearance, one hit, one at-bat,
    one out; a hit with two outs on the play is not a grounded-into double play. The earned-run replay and the 100-game generator implement the same distinction.
18. **Appeal plays are out of scope (owner decision, supersedes the "appeal as non-force out" simplification of the first remediation).** Not implemented:
    missed base, failed retouch, appeal third outs, fourth-out appeals. `RunnerPlayKind.Appeal` and `OutKind.Other` for runners are refused with
    `Game.appeal_not_supported`; a retouch after a caught ball and a base-touch out of a non-forced runner are refused instead of becoming tag outs. The Codex Medium finding is
    closed as an **approved scope exclusion**, not as an implementation. This is a game simplification, not a KBO or MLB rule statement.
19. **Rule-source policy refines D2 (it does not replace it): KBO first, 2026 OBR as approved fallback, then approved Star Player simplifications.** D2's career-frozen
    versioned snapshot, explicit simplifications and versioning are unchanged; `GameRuleSnapshot.RulePolicyId` records the policy. Each rule is classified
    `KBO_VERIFIED` / `OBR_FALLBACK_APPROVED` / `GAME_SIMPLIFICATION_APPROVED` / `UNRESOLVED` in `content/rules/game_rules_evidence.json`, with the sources actually read; an OBR fallback is
    never a KBO certification, "no KBO provision found" is never recorded as "KBO has none", MLB-only operating rules are not adopted (no automatic extra-inning runner,
    no three-batter minimum), and the 2026 OBR PDF (file download, unread) is not cited by clause number. *(Amended by items 23-26: the PDF was read on 2026-10-11.)*
20. **Gate rule.** A required rule that is `UNRESOLVED`, or a known conflict with KBO, keeps the Phase 2 Gate INCOMPLETE; passing tests are not evidence of an official rule.
    One required rule was unresolved: R02, a game still level after the 11-inning limit ends as a tie (no KBO text read, not an OBR concept). *(Resolved by item 23.)*
21. **DH switches split.** `DhMayBeForfeited` = the OBR-style "DH used on defense ends the DH" transition (on in the KBO-oriented profile as an OBR fallback, unverified for KBO);
    `FielderToMoundForfeitsDh` = the fielder-to-mound transition, labelled "invented, fictional profiles only" at the time. *(Corrected by item 25: it is OBR 5.11(a)(14) and is on in the KBO-oriented profile.)* Other OBR DH-ending triggers and replacing a pitching two-way DH are not
    implemented and are recorded as `UNRESOLVED` (not Gate-required) in the evidence file.
22. **Verification logs.** Log files are never overwritten by a later round: `PHASE_2_VERIFY_LOG_initial*`, `..._remediation1*` (+ the failed try), and the final-round
    `PHASE_2_VERIFY_LOG.md` / `_run1.md`.
23. **R02 is resolved by an owner application approval, not by a clause certification (2026-10-11, GPT Chat review).** A regular-season game still level after the 11th inning is a tie.
    Evidence: KBO board announcement 2025-01-22 (limit 11) and the official KBO news item of the 2026-06-03 Hanwha–Doosan game (3-3 after 11). The KBO league-regulation clause was not found, so the
    evidence status is `GAME_SIMPLIFICATION_APPROVED` with `clause_certified = false`; R02 is no longer a Gate blocker. This is separate from D2 certification of the profile, which stays incomplete.
    Notice 11795's "승부치기 10~12회, 이후 무승부" sentence is in the Futures-league item and is not first-team evidence (R28, deferred to a Futures profile).
24. **The 2026 OBR original text was read and is compared clause by clause.** Source: `docs/2026-official-baseball-rules.pdf` (SHA-256 in the evidence file). Result classes are `MATCH`,
    `KBO_PRECEDENCE`, `APPROVED_SIMPLIFICATION` (owner decision or recorded before the comparison), `PROPOSED_SIMPLIFICATION` (first recorded in the comparison, never called approved),
    `NOT_MODELLED` (input refused, safe side) and `OPEN_DEVIATION` (the engine differs and nobody approved it). Six open deviations were found and are **not** fixed in this round (no scope expansion):
    C12 double-play definition, C14 relief-pitcher earned runs, C19 box proof / left on base (measured: 70 of 200 team-games), C24 DH must bat once, C32 two-way DH entry, C34 relief walk-count table.
    The owner chose to FIX all six (items 27-31). *(Original text: "The owner chooses per item between fixing and accepting it as a recorded simplification. Until then the Phase 2 Gate is `INCOMPLETE`.")*
25. **DH classification corrected.** `fielder_to_mound_forfeits_dh` implements OBR 5.11(a)(14) (original text) and is no longer called invented or fictional. It is switched on in the KBO-oriented profile (one profile field;
    code and tests already existed) as an `OBR_FALLBACK_APPROVED` rule R27. Who fills the vacated position is an engine simplification (C29, awaiting owner confirmation). The profile content hash of
    `kbo-oriented-unverified-v0` therefore changes; no persisted game uses it yet.
    > **Superseded in part (added 2026-10-11, the original text above is kept as the history of that moment).** The "C29, awaiting owner confirmation" wording describes the state when item 25 was written, when the engine placed the DH into the vacated position automatically. That is no longer open: item 30 and evidence row C29 (`MATCH`, `fixed_on` 2026-10-11) replace it. Current policy: **no automatic placement** of the DH into a vacated defensive position; a legal substitution needs an **explicit Slot** naming the DH slot; unsupported substitutions are **refused with an error** (`dh_vacated_position_unspecified` and related codes). The latest status is in item 30 and the C29 row of `content/rules/game_rules_evidence.json`, not in this item.
26. **Evidence discipline.** MLB glossary sentences are explanation, never clause confirmation; every `OBR_FALLBACK_APPROVED` rule must have `obr_comparison` rows; an approval is never claimed for a difference
    nobody approved; `RuleEvidenceTests` and `BoxProofTests` guard this.
27. **C12 - double play vs grounded-into double play (OBR 9.11, 9.02(a)(17), 9.04(b)(1)).** `IsDoublePlay` / `FldDP` stay the defensive double play (two or more outs on a non-hit plate-appearance play);
    `GIDP` and the withheld RBI require a ground ball whose first two outs, in the verified order, are a force or a reverse-force double play (the batter-runner out on a ground ball is a force play; a reverse force needs the first
    out on the batter-runner or a runner behind and a runner whose force it removed). RBI is now credited after a non-force, fly or line double play (9.04(a)(1)); the error-between-putouts condition is not modelled (no error order in the input).
28. **C14 - earned runs per pitcher (OBR 9.16(i)).** `EarnedRuns.Reconstruct(half, limit, startIndex)` judges a pitcher's run in the inning reconstructed from his entry (real outs and runners at that moment), the team figure from the
    inning start; new `StatKey.TeamER` (appended at the end of the enum, team-level entry). The official examples (1)-(3) are hand-oracle tests. `PitchR` attribution was per runner at that time and is replaced by the slot ledger (C33, item 33).
29. **C19 - left on base and the box proof (OBR 9.03(c)).** A runner whose run was voided by the third out is left on base (once per runner key) beside the runners on base at the end; derived from each runner's final state, not a
    blanket +1. `BoxScoreReconciler` checks the proof; `BoxProofTests` asserts it exactly in all 200 team-games. The profile switch `CountWalkOffRunnersAsLeftOnBase` still decides the unfinished walk-off inning.
30. **C24 / C32 / C29 - DH rules (OBR 5.11).** `TeamGameState.StartingDh` (new, appended): the starting DH cannot be replaced before his first plate appearance unless the opposing club changed pitchers (`Game.dh_must_bat`);
    the two-way exception belongs to the starting pitcher listed as DH (`HasTwoWayStarter`); any other DH-slot player who goes to the mound ends the DH role (5.11(a)(12)) or is refused when the profile does not allow it; a fielder going to the
    mound (5.11(a)(14)) is processed only when the event names the DH slot in `Slot` - no automatic placement, other arrangements are refused. Event fingerprints already contain `Slot`; the `ef1` format is unchanged.
31. **C34 - walk charge after a pitching change (OBR 9.16(h)).** 2-0, 2-1, 3-0, 3-1 and 3-2 charge a following walk (and the runner) to the previous pitcher; all other counts and results belong to the reliever.
32. **Keeping rule-source blockers and implementation defects apart.** `gate_blockers` (required rules that are `UNRESOLVED`) is empty; `implementation_defects_open` and `pending_owner_decisions` in the evidence file track the
    remaining engine differences (C33 inherited-runner counting - Gate-required rule R17; C38 sacrifice-fly derivation - not Gate-required). They were reported, not decided, when this item was written (both are decided in item 33); a difference is never relabelled "approved" to close it.
    Rows touched by fixes carry `fixed_on`, `before_fix` and the names of their hand tests, and `RuleEvidenceTests` checks that those tests exist.

## Amendment after the owner instruction of 2026-10-11 (TASK.md): C33 final recording responsibility, C38 carry-over

33. **C33 - run responsibility is a slot ledger (OBR 9.16(g) and Comment, 9.16(h)(i), 9.17(d)); C38 is carried over.**
    - *Defect.* `BaseRunner.ResponsiblePitcher` was the runner's own pitcher and a run was charged to it. OBR charges "each pitcher with the number of runners he put on base, rather than with the individual runners", so Comment examples 2, 3, 5 and 6
      were charged to the wrong pitcher (and, through 9.17(d), possibly the wrong loser).
    - *Decision.* `ResponsiblePitcher` is now the responsibility **slot** a runner occupies. A batter who reaches on a fielder's choice that puts out a runner takes the slot of the runner put out (several runners of one pitcher: that pitcher's slot; of different pitchers: refused, item 34); a runner who is
      out any other way takes his slot with him; each run takes the oldest slot among the scoring runners and the runners left on base, and the slot the scorer carried goes back to a runner left on base. Pure function of the event order inside `FinishPlay`
      (`GameReducer.Responsibility.cs`): no new event or field, no randomness, event payloads and `ef1` fingerprints unchanged. R (`ScoredRun.ResponsiblePitcher`, one `PitchR` per run) and ER (the charged pitcher's 9.16(i) reconstruction, `TeamER`)
      stay separate; the loser is still the pitcher charged with the lead-taking run.
    - *Alternatives not chosen.* Swapping only the responsible-pitcher id on a fielder's choice (does not express example 6, where the scorers and the quantity differ); a per-pitcher inherited-runner count taken at the change (cannot follow
      slots that move by fielder's choices and by outs of different kinds); replaying the whole inning at each run (heavier, no extra rule coverage).
    - *Evidence.* Independent hand oracles from the rule text first (8 of 17 failed on the old engine, `docs/reports/PHASE_2_C33_RED.log [Git 제외 원본, 추적 요약: docs/reports/PHASE_2_RED_EVIDENCE.md]`), then the fix; a 30-game Python-scored set in which every game has a moved slot (the 100 games have none); negative control: 99 mismatches with the ledger off.
    - *Recorded limits.* Example 7's batter advance on the throw is not an event of the model (equivalent test used, no Gate effect); interference outs of a batter-runner are refused as before; a fielder's choice that puts out runners of different pitchers is refused (item 34).
      A profile `ContentHash` covers rule parameters only, so the changed charge is not visible in it; no game is persisted before Phase 4, which must store an engine rule version.
    - *C38.* Owner-approved Gate non-required carry-over: the basic sacrifice fly stays, line-drive, dropped-fly (error) and combined-out variants are documented as unsupported (never silently scored as a plain fly out by a new rule),
      re-evaluated in Phase 3 with the batted-ball and fielding event model. Nothing of C38 is implemented by this change.
    - *Gate.* Gate-required implementation defects: none open. The Phase 2 Gate stays INCOMPLETE until the independent re-review, the manual/FHD checks and D2 certification are done.

## Amendment after the Codex focused re-review (2026-10-11, High): ambiguous fielder's choice

34. **A fielder's choice that retires runners of different pitchers is refused (`Game.ambiguous_responsibility`).** Item 33 gave the batter the oldest slot when several runners were put out on one fielder's choice; the input cannot tell the out that is the fielder's choice (the slot passes on, 9.16(g))
    from an independent out on a runner's own advance (the slot disappears), so the choice was arbitrary and could charge the wrong pitcher. The event is now rejected in `FinishPlay` before any state is produced (after validation and order resolution; no receipt, state instance unchanged, same error on re-delivery).
    Condition: `FieldersChoice`, batter reaches, two or more runners put out, slots of more than one pitcher. Same-pitcher multiple outs, a single out and non-fielder's-choice results are unchanged. *Alternatives not chosen:* choose by the order of the outs (the order is scorer input and does not identify the cause of an out), choose the newest slot (equally arbitrary),
    add an input flag naming the fielder's-choice out (a new input model, outside this change). This is a **Phase 2 support limit by owner decision**, not an OBR or KBO rule statement; the Gate-required defect is closed by refusal, not by a new baseball rule. C38, the exclusion of appeal plays and the KBO-first / OBR-fallback policy are unchanged.

## Amendment after the Codex final focused review (2026-10-11, High): hit with a force out

35. **A hit is refused when the same batted ball forces out a runner (OBR 9.05(b)(1) first clause), `Game.hit_with_force_out`.** The check sits in `FinishPlay` after validation and order resolution and before any state or receipt, and uses the out classification derived from the state (`OutClassification.Force`: tag outs of forced runners count, a force removed by an earlier out is respected). It closes the bypass of the C33 refusal (item 34)
    by entering the same play as a `Single`. The engine does not convert a refused hit into a fielder's choice or a reach on error. Applied through the KBO-first / OBR-fallback policy (not a KBO certification). *Not done, recorded:* the second clause (forced out except for an error, row C43 `OPEN_DEVIATION`, reproduced and reported only), other hit-denial rules that need scorer judgement, and any judgement of whether an error caused a
    reach on error (row C42 `NOT_MODELLED`; `ReachedOnError` is neither certified nor refused wholesale). The "enter it as another result" hint of item 34 is valid only for the official classification of the real play. C38, the appeal exclusion, R02 and the policy are unchanged.

## Amendment after the C43 instruction (2026-10-11): errors that prevent a force out

36. **C43 fixed (OBR 9.05(b)(1) second clause) with a confirmed rule and an unsupported combination (docs/game-engine.md section 16).** (1) A hit whose play has a runner marked `ErrorSavedOut` whose would-be out is a state-derived force out is refused (`Game.hit_with_force_out_saved_by_error`); a force removed by an earlier real out is respected. (2) A hit with a runner on first, a recorded error and no error-caused move is refused as unsupported
    (`Game.hit_error_cause_unclear`) because the input cannot show whether the error prevented a force out. Both checks run in `FinishPlay` before any state, slot or receipt, never reclassify the result, and leave the state instance unchanged. *Alternatives not chosen:* forbidding every `Single` with an error (rejects clearly legal plays), crediting the hit unless proven otherwise (the reproduced defect), a new per-error cause input (new input model; deferred to Phase 3).
    *Approval status:* (1) is the original text under the approved policy; (2) is the **approved Phase 2 support limit C44** (evidence row C44, `NOT_MODELLED`), approved on 2026-10-11 by **GPT Chat's design judgement** relayed by the user in `TASK.md` (no separate direct owner approval is recorded; Claude Code did not approve it). Scope: an unexplained error on a hit with a runner on first is refused explicitly; `ErrorSavedOut` plus a verified force out stays refused by the C43 check; supported events such as one error with a matching `ErrorExtraBase` on a normal hit are kept; **2026-10-11 Codex Medium fix:** with a runner on first, two or more errors on a `Single`/`Double`/`Triple` are also refused (`Game.hit_error_cause_unclear`) whatever number of error-caused moves exist, because the event cannot link each error to its move; check order `hit_with_force_out` -> `hit_with_force_out_saved_by_error` -> `hit_error_cause_unclear`; multi-error plays can be legal in baseball and this is an input-model support limit, not a KBO/OBR rule; the RED log is `docs/reports/PHASE_2_C44_MULTI_ERROR_RED.log [Git 제외 원본, 추적 요약: docs/reports/PHASE_2_RED_EVIDENCE.md]`; not every hit with an error is rejected; an error of unconfirmed cause is never reclassified as another event. It is not KBO official certification and not a complete OBR implementation. C42 (`ReachedOnError` cause) stays `NOT_MODELLED`; C38, the appeal exclusion and the KBO-first / OBR-fallback policy are unchanged.
