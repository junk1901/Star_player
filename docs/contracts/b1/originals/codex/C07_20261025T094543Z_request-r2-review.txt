## 1. R2-A — INPUT_BUNDLE 독립 검수

승인 계약 §21은 실제 소비 입력 파일별 원본 보존을 요구한다.

Claude는 현재 필수 입력을 다음 4개로 보고했다.

- Environment Profile
- PZL Test Profile
- virtual_tuning_v4.json
- game_rules_profiles_v2.json

다음 사항을 검증한다.

1. 실제 실행·Replay·검증에서 소비하는 모든 입력 파일을 식별했는가?
2. SimHarness.csproj EmbeddedResource와 실제 런타임 소비 리소스가 일치하는가?
3. 튜닝·규칙 JSON의 실제 소비 바이트가 보존 원본과 일치하는가?
4. 필수 집합이 단순 제출 목록이 아닌 신뢰된 코드·빌드·실행 정보로 결정되는가?
5. 입력 누락·추가·교체·SHA 불일치가 발급 경계에서 거부되는가?
6. RAW_INVENTORY와 Receipt SourceFiles에 해당 원본들이 빠짐없이 포함되는가?
7. 현재 4개를 넘어 실제 소비 입력이 추가될 경우 누락을 탐지할 수 있는가?

또한 EmbeddedResource 바이트와 저장소 원본 파일의 대응이 Git 개행 설정이나 실행 환경에 따라 잘못 바뀌지 않는지 확인한다.

## 2. R2-B — PREFLIGHT 독립 검수

Claude는 Family 3개와 Unit 54개에 대응하는 PREFLIGHT 57개를 보존했다고 보고했다.

검증할 사항:

- 실제 첫 경기 전에 Preflight가 실행되고 기록되는가?
- Family 및 Unit별 필요한 기록이 모두 존재하는가?
- 기록은 기존 PreflightReport와 Manifest Attestation에 올바르게 결속되는가?
- 제출된 Preflight만 비교하지 않고 검증기가 직접 재실행·재계산하는가?
- 누락·변조·Unit 교체·중복을 모두 거부하는가?
- Attestation 또는 DIAGNOSTICS만 있는 경우 인증을 거부하는가?
- INPUT_BUNDLE과 PREFLIGHT를 모두 포함한 정상 Phase 영수증 발급이 가능한가?

Unit Preflight 레코드의 다음 값도 별도로 검토한다.

- run_status = NOT_STARTED
- error_code = Official.execution_not_implemented

이 값들이 실행 전 점검 상태의 합법적인 기존 표현인지, 또는 의미 충돌이나 OWNER 결정이 필요한 부분인지 판단한다.

## 3. 신규 입력과 빌드 재현성

현재 다음 상태가 보고됐다.

- 튜닝 JSON: 작업 트리 CRLF
- Git 원본: LF
- 빌드: 작업 트리 바이트를 EmbeddedResource로 사용
- core.autocrlf=true

이를 바탕으로 다음을 확인한다.

- 현재 Input SHA 및 Build Provenance의 실제 결속
- 다른 checkout 설정에서 바이너리 달라질 가능성
- 향후 공식 B-4 빌드 절차에 고정해야 할 바이트 정책
- 이 문제가 현재 B1 코드 수용 결함인지, 운영 Build Freeze 이전 해결 항목인지

검수 중 임의로 파일 개행을 변경하지 않는다.

## 5. 미결 OWNER·운영 사항

다음은 코드 수용 판정과 분리한다.

- 기존 OWNER 지시 원문과 저장소 승인 기록의 일치 여부
- Preflight 상태 표현의 계약 정합성
- B-4 공식 파일명과 입력 개행·빌드 재현성 동결
- 보호 앵커 디렉터리 설치
- AT-1\~AT-14r 및 정식 AT-4
- N27-d/e/f
- 승인 Environment Profile
- N12 비트 Golden과 witness_digest
- 운영 Build Provenance 및 검증기 바이너리 신뢰 경계

미실시 항목을 PASS로 처리하지 않는다.

## 6. 최종 판정

다음 항목을 각각 독립 판정한다.

- R2-A: RESOLVED / NOT_RESOLVED / INSUFFICIENT_EVIDENCE
- R2-B: RESOLVED / NOT_RESOLVED / INSUFFICIENT_EVIDENCE
- R1·R3·R4 회귀 여부
- INPUT_BUNDLE 계약 준수
- PREFLIGHT 계약 준수
- T10 수용 조건 충족
- B1 코드 구현 최종 수용 가능 여부
- 운영 Gate 잔여 사항

최종 T11 판정:\
PASS / FIX_REQUIRED / BLOCKED / INSUFFICIENT_EVIDENCE

PASS 가능 여부는 구현 수용 기준에 따라 판단하되, 운영 Gate 미완료를 숨기거나 Official Execution 준비 완료로 해석하지 않는다.
