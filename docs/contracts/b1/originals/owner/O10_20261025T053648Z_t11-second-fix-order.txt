Star Player — B1 T11 2차 FIX_REQUIRED 수정 지시
OWNER 작업 지시
Codex의 두 번째 T11 표적 재검수 결과는 FIX_REQUIRED다.
남은 Findings:

* R1 MAJOR — 검증 완료 객체 내부 가변성
* R2 MAJOR — Archive 필수 ORIGINAL 증거 누락
* R3 MAJOR — Phase 원본 합성 시 Artifact ID 충돌
* R4 MINOR — Archive 루트 생성 전 경로 안전성

이번 작업에서는 위 4건만 수정한다.
새로운 설계나 승인 계약 변경은 요청하지 않는다.
1. 작업 지시서 작성
먼저 다음 파일을 작성한다.
`docs/tasks/B1_T11_FIX_R2_TASK.md`
다음 내용을 포함한다.

* Codex R1~R4 원문 지적 및 재현 경로
* 승인 계약의 해당 조항
* 수정할 파일과 함수
* 수정 방식과 선행 의존성
* Red/Green 회귀 시험
* 완료 기준
* 현재 Git 및 보호 SHA
* 작업 재개 방법
* Codex 재검수 제출 자료

루트 TASK.md는 NSC-6 OWNER 증거로 보호된 파일이다. 절대 수정하지 않는다.
작업 진행 상태는 기존 구현 로그와 별도 보고서에 남긴다.
2. R1 — 검증 후 가변 데이터 변경
다음 경로를 수정한다.

* EvidencePayload.Canonical
* VerifiedFamily 및 검증 결과의 SourceFiles
* 내부 JObject/JArray 참조
* Certification 발급 경계

인증 세션은 검증이 끝난 시점의 불변 스냅샷을 소유해야 한다.
발급 시 사용하는 Canonical 바이트, A+, SourceFiles 및 Inventory는 그 스냅샷에서 일관되게 도출한다.
외부에서 공개 객체의 배열이나 컬렉션을 수정하더라도 이미 검증한 원본이 변경되어서는 안 된다.
필수 반례:

* Canonical[0] 변경
* SourceFiles에 파일 추가
* SourceFiles에서 파일 제거
* SourceFiles의 Raw SHA 변경
* 중첩 JObject/JArray 변경
* 검증 결과 객체와 발급 데이터의 불일치

발급은 검증 당시 스냅샷을 정확히 사용하거나 불일치를 거부해야 한다. 변경된 바이트에 기존 A+를 붙여 발급하는 경로는 금지한다.
3. R2 — Archive 필수 ORIGINAL 완전성
승인 계약 §21의 필수 보존 목록을 실제 검증·발급 경계에 적용한다.
현재 Unit별 필수 개수 검사뿐 아니라 다음을 포함한다.

* APPROVAL_RECORD
* BUILD_PROVENANCE
* INPUT_BUNDLE
* 필요한 PREFLIGHT
* REGRESSION_PROOF
* 그 밖에 §21에서 해당 검증 범위에 필수인 ORIGINAL 역할

필수 역할과 개수는 신뢰된 승인 계획 및 실제 검증 입력에서 도출한다.
제출자가 제공한 ORIGINAL 목록과 RAW_INVENTORY가 서로 같다는 사실만으로는 통과시키지 않는다.
실제로 검증에 사용한 승인·빌드 원본의 바이트와 SHA를 Archive 스냅샷 및 영수증 source_files에 결속한다.
필수 반례:

* APPROVAL_RECORD 누락
* BUILD_PROVENANCE 누락
* 승인 원본과 Inventory 양쪽에서 동시 제거
* Build 원본과 source_files 양쪽에서 동시 제거
* INPUT_BUNDLE 누락 또는 불일치
* 필요한 PREFLIGHT·REGRESSION_PROOF 누락
* 정상 ORIGINAL 전체를 보존한 양성 시험

기존 TestOnlyWorld의 성공 Fixture가 필수 원본을 누락한 상태라면 Fixture도 계약에 맞게 수정한다. 누락을 허용하도록 검사를 약화하지 않는다.
4. R3 — Phase Artifact ID 충돌
다음 코드를 중심으로 수정한다.

* EvidenceWriter의 Artifact ID 생성
* Certification의 Phase 원본 합성
* RAW_INVENTORY 및 source_files 생성

현재 artifact_id만으로 GroupBy한 뒤 첫 번째 항목을 선택하는 방식은 제거한다.
서로 다른 원본이 동일 Artifact ID를 갖는 경우 조용히 하나를 선택해서는 안 된다.
Calibration, Integration, Dominance의 원본을 Phase 범위에서 유일하게 식별하도록 한다.
동일 ID가 서로 다른 경로·SHA·내용을 가리키면 오류로 거부한다.
합법적인 동일 원본 재참조는 계약이 허용하는 조건에서만 처리한다.
필수 시험:

* 정상 세 Family 원본 합집합 보존
* Calibration/Integration 동일 ID 충돌
* 동일 ID, 다른 SHA
* 동일 ID, 다른 경로
* 원본 목록에서 한 Family가 유실되는 상황
* Phase Inventory와 Receipt SourceFiles 전체 결속

정상적인 세 Family로 Phase 영수증까지 도달하는 양성 경로를 시험한다.
부적격 자식 거부 시험만으로 Phase 발급 성공을 증명하지 않는다.
5. R4 — Archive 루트 생성 경계
기존 Archive.WriteNew 및 PinnedDirectory 경계를 검토한다.
비신뢰 경로에 대해 Directory.CreateDirectory(root)를 안전성 검사보다 먼저 실행하지 않는다.
허용되는 구현 방향:

* 검증된 부모 핸들에 상대적인 안전한 생성
* 또는 사전에 안전하게 준비된 루트만 받는 방식

기존 PathSafety 규범을 유지하고 Reparse Point 및 경로 교체 공격을 거부한다.
필수 반례:

* 부모 경로가 Junction일 때 Archive 루트 생성 시도
* 거부 전에 외부 디렉터리가 생기지 않는지 확인
* 정상 보호 루트 생성 또는 사용
* 파일 생성 후 부모 경로 교체
* 영수증 재시도 읽기

외부 증거 파일 생성만 막는 것으로 완료 처리하지 않는다. 경로 검증 전에 발생하는 외부 디렉터리 생성도 막아야 한다.
