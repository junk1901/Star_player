Star Player — B1-T00~T11 일괄 구현 작업
OWNER 작업 지시
B1-T00~T11 전체를 하나의 구현 작업 묶음으로 진행한다.

* 구현 담당: Claude Code
* 독립 검수 담당: Codex
* 검수 방식: 모든 구현 및 내부 테스트 완료 후 Codex 통합 독립 검수 1회
* 중간 TASK마다 Codex 검수를 요청하지 않는다.
* 각 TASK 내부의 테스트·회귀 검증·문제 수정은 생략하지 않는다.

1. 기준 계약
최종 기술 계약:
`B1-T00_FINAL_CONTRACT_DRAFT.md`
승인 검토 대상 SHA-256:
`1338a2f7e4bf2e95e9cbc3aa6ff29364791b8d774965dbce73a1e329a7b97d64`
기존 검수 결과:

* READY_FOR_OWNER_APPROVAL
* SOURCE_RECONCILED

먼저 OWNER 승인 기록이 실제로 확정됐는지 확인한다. 이 작업 지시는 일괄 구현 범위의 허가이며, 미기록 OWNER 계약 승인을 임의로 만들어 내는 허가는 아니다. 승인이 이미 확인되면 재승인 없이 진행한다. 아직 미승인이라면 승인 기록을 준비하고 명시적인 OWNER 승인 확인 후 구현한다.
실제 Git HEAD, TASK.md SHA 및 작업 트리를 확인한다.
현재 TASK.md는 NSC-6 OWNER 결정 증거이므로 원본을 보존한다. 구현 계획의 원천은 S00.5 §5~§6과 최종 B1-T00 규범 문서다.
2. 구현 범위
기존 S00.5의 T00~T11 정의와 최종 계약의 후행 수정 사항을 함께 적용한다.
의존성에 따라 다음 순서로 진행한다.
A. 계약 기준본

* T00: OWNER 승인 기록, 기준본 보존, 필드 사전·Traceability 및 필요한 계약 문서 정합성 처리

B. 기반 기능

* T01: Strict JSON Reader 및 4Schema Validator
* T02: JCS / U64 / F64 정규화
* T04a: GameExecutor 사건별 관찰 Seam

C. 증거 생성

* T03: Family/Dominance 공식 문서 생성
* T04b: Unit PZL 및 GAME_EVENTS 번들
* T06a: Approval Record Reader 및 Trust Anchor 검증
* T08: Archive / RAW_INVENTORY

D. 독립 검증

* T05: 공식 PZL #6 및 고정 20경기 검증
* T07: A+ Canonical Payload와 의미 Hash
* T06b: 통합 EvidenceVerifier

E. 인증 및 최종 테스트

* T09: Receipt / Registry / 멱등 등록
* T10: 독립 Golden, 기존·신규 반례, 전체 회귀 테스트

각 작업은 선행 의존성 충족 후 진행한다. 실제 코드 구조와 후행 계약에서 의존성이 더 엄격해졌다면 최종 승인 계약을 우선한다.
3. 중간 검수 정책
Codex 리뷰는 마지막까지 요청하지 않는다.
대신 각 구현 구간마다 Claude가 직접:

* 필요한 단위 테스트와 회귀 테스트 실행
* 실패 원인 분석 및 수정
* 기존 Hash·RNG·Replay·Gate 불변성 확인
* 변경 파일과 테스트 결과 기록
* 구현 누락·규범 충돌 여부 자체 점검

을 수행한다.
T03과 T04a는 기존 결과 바이트 및 RNG 불변성을 특별히 검증한다.
4. 미해결 OWNER Gate

* NSC-4: T06a Trust Anchor 구현·배치 전 해결
* NSC-5: T09 Registry 서비스 설정 Reader/Writer 구현 전 해결

기존 OWNER 결정 기록을 먼저 확인한다. 이미 결정된 사항이면 적용한다.
아직 미결이라면 선택지와 권장안을 보고하고 OWNER의 명시적인 결정을 요청한다. 미결 상태를 임의 승인하거나 해당 수용 시험을 PASS 처리하지 않는다.
Windows 보안 검증 AT-4(P-1)를 비롯한 필수 실측은 실제 수행한 결과만 기록한다. 수행할 수 없는 환경이면 미검증 상태와 차단 범위를 정확히 보고한다.
5. 변경 제한

* 기존 ResultHash·ConfigHash·Attestation Hash 불변
* RNG 소비 및 Replay 순서 불변
* DRAFT 원본 바이트 불변
* OfficialApprovals.Current 차단 정책 유지
* 승인 없는 계약·통계 정책 변경 금지
* 공식 Seed·운영 SID·Golden 임의 승인 금지
* 현재 TASK.md 및 사용자 PDF 원본 변경 금지
* Git Commit·Push는 별도 승인 없이는 수행하지 않는다.

Official Execution = NOT_READY
Final Execution Freeze = PENDING
이번 구현 묶음에서 공식 대규모 실행이나 Final Execution Freeze를 진행하지 않는다.
6. T10 완료 기준
전체 문서 Golden을 독립적으로 작성·검증한다.
기존 28개 반례, 후행 계약의 신규 반례, NSC-6 coverage 반례를 포함한다.
전체 Release 테스트 및 verify.ps1을 실행한다.
단순 빌드 성공이나 테스트 통과 수치만으로 완료를 주장하지 않는다. 계약별 수용 기준과 실제 증거를 연결한다.
7. Codex 제출용 최종 산출물
중간 보고는 내부 작업 기록으로 유지하고, 전체 구현이 끝나면 다음을 하나의 통합 보고서로 제출한다.

1. T00~T10 각각의 구현 및 수용 기준 충족 여부
2. 변경 파일·클래스·주요 동작
3. 실제 수행한 테스트와 PASS/FAIL/SKIP
4. Hash·RNG·Replay 불변성 증거
5. Golden 및 변조 반례 결과
6. NSC-4·NSC-5와 Windows 실측 결과
7. 기존 계약 대비 변경 사항
8. 미완료·차단·미검증 항목
9. Codex T11 독립 검수 체크리스트
10. Git HEAD·작업 트리 상태·변경 파일 목록

T10까지 완료되면 작업을 멈추고 최종 보고서를 제출한다.
그다음 Codex가 T11 통합 독립 검수를 수행하도록 한다.
Codex 검수 전에는 T11을 PASS로 표시하지 않는다. Codex 결과에서 발견된 결함은 별도로 수정하고, 필요한 경우 재검수를 받는다.
B-1 완료를 Phase 3 전체 완료 또는 Official Execution 승인으로 간주하지 않는다.
