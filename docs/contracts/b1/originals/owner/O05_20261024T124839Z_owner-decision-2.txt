Star Player B1 — OWNER 추가 결정 및 T11 이전 마무리
B1 자체 검증 2,972 PASS 결과를 확인했다. 중간 Codex 검수 없이 기존 승인 범위의 마무리 작업을 계속한다.
결정 1 — NSC-4
기존 B안의 보안 목표를 유지하는 최소 정정을 승인한다.

* INHERIT_ONLY ACE는 해당 객체에 실제 적용되는 ACE와 구분한다.
* 자식 객체에 상속되어 적용될 수 있는 ACE까지 무조건 무시하지 않는다.
* 상위 디렉터리는 앵커 경로의 삭제·이름 변경·교체·권한 변경 가능성을 기준으로 검사한다.
* 보호된 앵커 파일과 디렉터리에 비TCB 주체의 실질적 변경 권한을 허용하지 않는다.
* 경로 구성요소의 Reparse Point와 신뢰할 수 없는 경로 대체는 계속 거부한다.
* ACL 검사 오류 또는 신뢰성을 입증할 수 없는 경우 Fail-Closed로 처리한다.

실제 Windows에서 테스트 가능한 보호 디렉터리 후보와 적용 ACL을 제시하고, 정상·공격 반례로 검증한다. 운영 환경이 검증되지 않은 경우 PASS 처리하지 않는다.
결정 2 — T05
독립 EvidenceVerifier가 기존 Infrastructure의 실제 #6 v2 JSON Writer/Reader를 재사용할 수 있도록 최소 공개 진입점 하나를 추가하는 방식을 승인한다.

* 기존 codec의 복제 구현 금지
* 기존 JSON 형식·Hash·RoundTrip 의미 변경 금지
* 무관한 internal 형식의 공개 확대 금지
* 기존 경계 테스트가 필요한 최소 예외만 승인 근거와 함께 수정
* 검증기 단독 실행에서 #6 정상·변조 반례 모두 시험

결정 3 — T09 Registry ID
모든 일반 응답에 포함된 Registry ID를 사후 비교하는 해석 대신, 명시적인 초기 조회를 채택한다.
닫힌 요청 형식에 읽기 전용 `get_registry_identity` 연산을 추가한다.

* 기존 Pipe Owner·DACL·클라이언트 신원 검사를 먼저 수행한다.
* 같은 인증된 연결에서 Registry ID를 조회한다.
* Trust Anchor의 registry_instance_id와 일치해야만 다른 Registry 연산을 진행한다.
* 불일치·오류·연결 교체 시 즉시 Fail-Closed
* 기존 Register 권한과 기존 요청 3종의 의미는 변경하지 않는다.

이 추가 요청과 응답 형식만 별도 OWNER 결정 기록에 명시하고 필요한 Schema·회귀 시험을 갱신한다.
남은 검증과 계약 정리

* 이번 세 가지 결정을 별도 결정 기록에 남긴다.
* 기존 승인 계약 SHA는 변경하지 않는다.
* 통합 보고서 7절의 OWNER 결정 대상 해석 1·2·3·6번은 원문을 대조한다. 이번 결정으로 명시적으로 해결되지 않은 사항은 임의 승인하지 말고 결정 표로 보고한다.

* Windows 별도 계정 실측이 필요한 AT 시험은 현재 자체 테스트와 분리한다. 계정 생성이나 운영 보안 설정 변경은 별도 허가 전에는 수행하지 않는다.
* 실제 운영 환경 프로필 승인값과 비트 Golden은 임의 생성하지 않는다.
