2. 수정 범위
주요 검토 대상:

* RequiredOriginals.cs
* PreflightRecords.Verify
* SameMembers
* FamilyOfficial.cs / DominanceOfficial.cs

현재 결함:
SameMembers는 일부 필드의 이름과 순서만 확인하고 실제 값은 검사하지 않는다.
Preflight를 독립 재실행했음에도 제출 기록의 일부 결정적 필드가 다른 경우 이를 거부하지 못한다.
3. 수정 요구사항
독립 재실행에서 생성한 기대 Preflight 기록과 제출된 기록을 비교한다.
비교 대상은 기존 계약과 현재 공식 Preflight 형식이 정의한 모든 결정적 필드다.
반드시 다음을 포함한다.

* preflight.games_per_cell
* schema_status
* official_evidence
* complete
* family_gate
* dominance_gate
* 기타 Family 및 Dominance Preflight에 존재하는 결정적 필드 전체

검사는 다음 조건을 만족해야 한다.

1. 필드 이름과 순서를 검증한다.
2. 필드 타입을 검증한다.
3. 결정적 필드의 실제 값을 비교한다.
4. 중첩 객체와 배열의 내용도 비교한다.
5. 필수 필드 누락·추가·중복을 거부한다.
6. 제출된 값을 그대로 기대값으로 사용하는 자기 검증은 금지한다.
7. 기대값은 신뢰된 승인 입력과 독립 재실행 결과에서 도출한다.
8. Raw SHA와 길이가 일치하더라도 결정적 값이 다르면 거부한다.
9. 기존에 명시적으로 비교 제외된 환경·출력 경로 항목의 정책은 유지한다.
10. 비교 제외 범위를 새로 넓히지 않는다.

전체 JSON 바이트 동일성이 적합하지 않은 경우에는 기존 비교 제외 규칙을 적용한 결정적 필드 투영을 만들어 정확히 비교한다.
A+에서 제외된 필드라는 이유만으로 Preflight 내용 비교에서도 제외해서는 안 된다.
기존 오류 분류 및 Fail-Closed 정책을 유지한다.
4. 필수 RED/GREEN 시험
수정 전에 기존 결함을 재현하는 실패 시험을 작성한다.
정상적인 Preflight 원본을 기준으로 각각 다음을 변조한다.

* games_per_cell 변경
* schema_status 변경
* official_evidence false → true
* complete false → true
* family_gate 변경
* dominance_gate NOT_EVALUATED → PASS
* 결정적 숫자·문자열·boolean의 타입 변경
* 중첩 결정적 필드 변경
* 필수 필드 누락 또는 불필요한 필드 추가

특히 다음 반례를 반드시 포함한다.

1. 정상 Preflight를 생성한다.
2. 결정적 필드 하나를 변경한다.
3. 변경된 파일의 Raw SHA와 byte_length를 재계산한다.
4. 필요한 ArtifactRef·Inventory 참조도 일관되게 갱신한다.
5. 검증을 다시 수행한다.
6. 단순 SHA 불일치가 아니라 Preflight 내용 검증에서 거부되는 것을 확인한다.

정상 기록은 그대로 통과해야 한다.
수정 전 실패 및 수정 후 성공 증거를 각각 보존한다. 수정 전에 실행하지 못한 시험은 RED 실행 완료라고 주장하지 않는다.
